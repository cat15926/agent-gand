# 平台协作修复进度（2026-10-10，第四批）

本批从 10 月 10 日开始实施，最终核验于 10 月 11 日完成。

对应 [Issue #14](https://github.com/cat15926/agent-gand/issues/14)，承接[第三批进度](./platform-collaboration-repair-progress-2026-10-10-batch3.md)。本批保留现有未提交变更，接入可选的逐阶段执行门禁。

## 本批实现

- 阶段分工编译为现有 Coordination 步骤图，阶段内明确成员任务顺序派发；当前阶段交付后停止，用户验收通过才启动下一阶段。旧的执行结束后验收保持原行为。
- 平台派发确认来自持久化步骤认领，区别于模型回复和业务验收。当前回合只注入当前阶段清单；验收证据限定为当前阶段已完成的成员步骤及当前计划工作区文件。
- 普通恢复与计划修订不能绕过验收；拒绝不会重跑；接受后崩溃可由原执行器恢复；取消及原终态保持不可复活。
- 阶段时间预算与模型 API 输出 Token 总预算已接入；阶段与 Run 共享事务预约，未知消耗保留额度并阻止新派发，终态的明确业务结束不会释放这些额度。SDK/Codex 使用时间预算，拒绝无法落实的 Token 硬限制。
- 页面新增方式选择、阶段成员任务编辑、预算预览、派发与执行状态以及“验收通过并继续执行”。追加数据库迁移 v3，防止旧 worker 忽略强制阶段门禁。

详见[逐阶段执行与用户验收门禁](../architecture/business-stage-execution-v1.md)。

## 验证

新门禁夹具已通过 Runtime execute 和兼容 off 模式，包含实际 Claude SDK → Codex app-server 驱动与本地 stdio 模拟进程、API 请求、Owner HTTP 注入及恢复；还验证原生写入前审批、文件哈希变化、后续 Codex 阶段超时保留已验收结果，以及阶段图成员数与动态单次派发限制的区别。类型检查、Web 构建、模型超时、业务验收及 O1/O4/O6 回归通过；O6 的子进程身份检查在沙箱外的临时夹具环境通过。全部测试不请求真实模型。

浏览器工具仍因 trusted Node 进程退出不可用，本批使用本地无头 Chrome、全新临时资料、内存 HTTP/事件注入完成页面回归，不监听端口。阶段编辑、分工/预算预览、交付登记、Cookie/CSRF、勾选验收、自动继续、当前阶段证据筛选和 390px 布局检查通过，桌面与移动端截图已经人工核看。产物位于 `apps/server/data/business-stage-ui-qa/`，测试命令见架构文档。此页面测试不代表真实网络/WS 传输通过；真实模型与此前 Runtime 控制联合夹具仍未完成。
