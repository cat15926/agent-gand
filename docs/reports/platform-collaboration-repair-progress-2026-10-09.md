对应 [Issue #14](https://github.com/cat15926/agent-gand/issues/14)、[原始报告](./platform-collaboration-gaps-2026-10-08.md)及[第一批修复](./platform-collaboration-repair-progress-2026-10-08.md)。第一批已提交并推送至 `origin/main`：`fdb15e7`。

## 本批接入

实现可选的任务级阶段验收清单，覆盖冻结入口、草稿与预览、交付证据选择、逐项验收、验收历史及独立业务结果。详见[阶段与业务验收 v1](../architecture/business-acceptance-v1.md)。

执行终态与业务结果分开：旧任务没有清单时显示目标未验收；有清单的任务执行收敛后等待用户验收。确认收到不能通过，全部必要交付、标准及前置阶段满足后才能验收。业务结果可区分全部达成、明确未达成、接受部分结果和用户提前结束。

验收使用追加账本、版本校验、幂等请求和证据哈希重验。原 Run、冻结请求及 Runtime 终局不被业务验收改写。HTTP 验收入口复用既有管理会话、Host/Origin 与 CSRF 校验，浏览器自动连接本地管理会话。阶段清单不成为房间默认偏好，图修订保留原清单；当前跨 Run 恢复暂时阻断有清单的任务，避免契约遗失。

## 交互验收路径

“执行设置 → 本任务启用阶段验收 → 填写阶段、标准、必要交付 → 预览并确认 → 等待执行结束 → 查看计划、结果与验收 → 登记交付候选 → 逐项核对 → 确认本阶段”。

提前结束先取消执行，再固定业务结果和原因。拒绝候选需填写原因；旧证据与决定保留在验收历史中。

## 验证范围

新增 `verify:business-acceptance` 已通过，覆盖契约冻结、预览漂移、仅确认收到、漏交付/漏标准、跨 Run 与用户需求拒绝、文件/消息漂移、未知执行围栏、顺序验收、幂等/CAS、三种引擎的业务状态、实际 Coordination Attempt 输出、部分接受/提前结束、原终态不可变、冷进程重建、HTTP 接口、草稿恢复及默认偏好隔离，以及实际 Web 客户端的管理会话建立与错误码传递。使用临时数据库、Fastify 注入和 1 次本地 mock 回合，不调用真实供应商，不监听端口。

既有 `verify:run-continuation`、`verify:runtime-context` 和 `verify:runtime-completion-integration` 已通过。`verify:orchestration-o1`、类型检查、Web 构建、文档链接及 diff 检查也已通过。构建仍提示现有较大 bundle，不影响本批构建成功。
