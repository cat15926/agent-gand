# 本地普通聊天室狼人杀失败分析

日期：2026-10-17。状态：只读分析完成；未修改业务记录、重发请求或实施修复。

分析对象为本地最新 Run `d95aa48c-23bd-4746-91bd-17ee7080f509`，房间 `d476f9ff-81f8-40fc-997e-81a87d5a45ff`。用户目标是“组织一场狼人杀游戏，我作为观众参与游戏，你们选出法官角色，来推进游戏”。记录时间为北京时间 02:35:42 至 03:49:10，最终 failed。

**结论：游戏首先被旧协作路径的私密来源权限阻断，反复请求用户确认仍未推进；最终一次恢复又遇到本机合盖休眠，醒后执行租约检查失败。最新这场的 600 秒配置已生效，继续加时或加 Token 无法修复权限和编排缺口。**

## 1. 实际执行路径

参与者是 5 个 Claude SDK 成员（鸡腿、nim、找茬员、小牛吗、大聪明）和 1 个模型 API 成员 `glm53-api`。入口选择 `dynamic_collaboration`，最初唤起鸡腿，由其移交小牛吗主持。

冻结契约为 `controlActionVersion=2`、`toolApiVersion=2`。没有 `scopedCollaboration` 能力包；该 Run 的 `scoped_delivery_plans`、`information_release_workflows` 和 `information_release_records` 均为 0。加入一个模型 API 成员没有把普通任务自动转成新 Scope/发布流程。

普通 Collaboration 调度器仍冻结 v2 契约，见 `apps/server/src/collaboration/scheduler.ts`。独立材料和专用发布入口是另外的受保护准入路径；G5 原生新能力包尚未开放，参见[实施指导](../plans/scoped-collaboration-implementation-guide.md)与[支持矩阵](../architecture/scoped-collaboration-support-v1.md)。

## 2. 首个持续阻断：私密汇总污染后续调度范围

02:41:30，法官收到首批两名玩家的私密结果。实际汇总消息的访问范围为 `["role-a614a094","user"]`，即法官和 Owner。此后法官继续向尚未领牌的玩家征询，被拒绝：

> 私密来源不在目标成员的可见范围内，即使再次声明 private 也不能扩大授权

该桥接错误在 02:43:06 至 02:49:11 出现 **4 次**。之后法官尝试以公开交接启动“信使制”，又被拒绝：

> 私密来源不能改为公开投递，请由所有者提供授权摘要

该桥接错误在 02:56:07 至 03:04:57 出现 **3 次**。这里统计独立 `bridge:*` 错误；对应 native tool span 是同一失败的另一层记录，不重复计数。

代码位置为 `apps/server/src/collaboration/controlTools.ts` 的 `validateRecipientAccess`：检查的是当前回合已继承的私密来源范围，不会仅凭模型声称“本段文字不涉密”允许扩权。正确的继续方式需要新的独立执行范围、明确输入材料及必要的专用披露授权，而普通路径没有自动创建它们。直接删除这个检查会扩大私密信息暴露范围。

只有首批两名玩家实际完成子调用，其余三名玩家没有被成功调度。游戏一直没有完成第一夜。

## 3. 用户文字确认没有转成可执行授权

法官提出 A/A1“信使制”，多次请求观众复制指令、允许公开摘要或等待玩家主动报到。实际记录为 **4 次 user_decision Hold、2 次 timer Hold**；但没有创建 G3 发布授权，也没有产生成功的公开玩家激活交接。

部分模型输出声称“指令已发布生效”“等待玩家报到”，这些叙述并不对应新的玩家 Dispatch 或公开发布记录。普通回答不能改写已有私密来源范围，也不能替代专用发布批准。平台缺少在此处核对交付事实、阻止重复无效方案并给出明确可继续路径的产品闭环。

03:08:01 又触发运行总时长预算，用户于 03:08:46 增加预算 100% 后继续。这与单次回复超时是不同限制；延长总时长没有解决既有权限阻断。

## 4. 最终终止：休眠后的租约失效

最新这场所有 SDK 执行记录的 `timeoutPolicy.configuredMs` 和 `effectiveMs` 均为 **600000**，冻结账户连接版本为 2。最终执行的截止时间也明确为 03:41:46.957，说明 10 分钟设置已实际进入执行器。

本机 `pmset -g log` 的相关记录与运行时间对应如下：

| 北京时间 | 证据 |
|---|---|
| 03:14:46 | 法官创建 5 分钟 timer Hold，计划 03:19:46 唤醒 |
| 03:16:35 | 系统因 `Clamshell Sleep` 进入睡眠 |
| 03:31:46 | 系统 DarkWake；过期 timer 此时才恢复，法官新 Attempt 被认领 |
| 03:31:51 | 系统再次进入睡眠，记录持续 1038 秒 |
| 03:49:09 | 系统再次 DarkWake |
| 03:49:10 | 外部执行记录 cancelled，错误“执行或责任代际已失效”；Run 随后 failed |

终态消息进一步记录“执行尝试租约已失效”。`execution/runner.ts` 每 100ms 检查执行授权，`execution/authority.ts` 要求租约有效；系统睡眠期间 JavaScript 定时器和续约无法正常运行，醒后会面临过期边界。最后这次执行的墙钟跨度约 17 分 23 秒，不应解释成配置没有改为 10 分钟。

休眠记录、恢复延迟和终止时间相互吻合，证明本次存在主机睡眠因素；具体授权检查、超时和租约续约回调的先后顺序没有逐回调日志，也没有在此轮做休眠故障注入，不能把其精确竞争顺序写成已复现结论。产品仍需补齐休眠/长暂停后的诊断分类与保守恢复处理。

## 5. 与此前成功验证的差异

| 维度 | 此前成功验证 | 本次用户聊天室 |
|---|---|---|
| 主持与阶段推进 | 验收脚本维护规则、身份及阶段状态 | 模型自行选法官、制定规则和推进 |
| 参与后端 | 全部模型 API | 5 个 Claude SDK + 1 个模型 API |
| 控制协议 | v3 独立材料/Scope | v2 普通协作 |
| 私密上下文 | 每份行动独立 Scope，父级只见固定状态 | 法官正文汇总后继承私密范围 |
| 公开内容 | 脚本按规则整理公告，测试 Owner 调用确切内容批准及发布接口 | 模型请求普通公开交接；没有专用发布授权 |
| 终局规则 | 固定 1 狼、1 预言家、3 村民 | 模型选择 2 狼、预言家、女巫、村民 |

此前成功证明的是结构化 API 流程及显式继续能完成游戏，不能作为普通聊天室自由文本、多 SDK 成员、用户仅作观众的全自动狼人杀验收通过证据。此前面向用户的说明应更突出这个覆盖范围。

## 7. 后续修复方向

1. 在普通入口识别并展示跨私密/公开、多阶段任务所需的能力，接入独立 Scope、状态调度及受控发布；不支持的后端组合在执行前给出明确限制。
2. 将身份发放、行动接收、阶段推进和消息发布落实为可核对的事实，禁止用“已发送”的自然语言取代成功回执；避免无有效待办却反复等待玩家。
3. 将通用的阶段披露规则做成可批准契约；用户仅当观众时，需要预先授权的确定性投影或披露策略，不能靠普通聊天确认扩大范围。自由文本自动披露仍须单独设计。
4. 补齐 G5 原生 Scope/发布支持及真实验收，再开放相应 SDK 组合。
5. 为主机长暂停补充休眠/事件循环延迟与租约过期诊断、未知调用保留和安全继续路径，避免只展示泛化的“责任代际失效”。
