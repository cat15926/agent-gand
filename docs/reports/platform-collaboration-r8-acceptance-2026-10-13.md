SDK/API 使用各自现有连接，没有依据早期报告自动修改 Base URL 或认证头。真实任务成功证明这些选定版本在本轮可用，不能推导其他账户、模型或套餐组合可用。原生刷新令牌以同身份及文件 CAS 同步回源；原账户登录代次仍为 2，连接和角色版本没有改动。最后对原 Codex 身份执行 `account/read(refreshToken:false)`，认证通过、模型 turn 为 0。报告及提交中不含凭据。

## 本轮发现与修正

真实 Codex 能做文本任务，却无法发现文件工具，实际输出明确报告 `code-mode host is disabled`，没有 `fs.write` 账本或文件。修正双向 Driver 的宿主开关后完成上表真实写入恢复；代码执行、shell、浏览器和其他普通原生工具限制保留。验收始终检查真实字节，不将“模型生成了正文”当作文件已交付。

复制原生登录目录进行隔离测试会使刷新后的令牌只留在副本。补充同一身份、登录代次及源文件摘要的条件同步，使用已成功副本恢复同一账户，再完成 Codex 复测。测试覆盖源文件被用户修改、身份变化、代次变化与非归属进程拒绝。

早期验收脚本也出现错误：契约字段与现有 schema 不符、返工集合未按当前阶段过滤、对用户取消任务误尝试续跑、工作区空值覆盖、Undici 8 回调不匹配、浏览器默认展开及自动抽屉/按钮标签假设。原始失败和消耗均保留；在专用夹具修正后补测，没有篡改旧 Run 为成功，也没有放开用户取消、未知副作用或 Owner 门禁。

## 工程及证据层级

- `pnpm verify:platform-real-acceptance`：隔离、准入触发器、真实本机 Undici 响应丢失、进程归属、Owner/CSRF、原生令牌 CAS；供应商请求为 0。
- `pnpm verify:codex-mcp-protocol`：实际 Codex 发现 MCP 工具，关闭代码执行及 shell；未发送模型 turn。
- `pnpm verify:private-write-recovery`、`pnpm verify:stage-scheduling`：私密恢复、预算、scope、原生绑定及零重放回归通过，均为隔离模拟模型。
- Shared/Server/Web 类型检查、Web 构建、文档链接、diff 格式及九个新增入口/辅助脚本语法检查通过；保留既有大 chunk 提示。
- 实际 Chrome 的 1440px、390px 任务/调度面板与预览无横向溢出，浏览器页面无 React 异常；静态资源来自构建文件，API/WS 没有被模拟。

## 调用与费用口径

最终调用汇总以该目录全部验收库的实际账本为准，包含调试、认证失败、故障注入及重测。模型 API 请求和原生启动分别计数，原生内部推理请求次数未知。已知后端报告与未确认占额分开列示，结转记录不重复汇总。它们不是供应商发票，不能作为实际扣费保证。

本轮账本合计 **49 次平台准入启动**：模型 API **30** 次、Claude SDK **13** 次、Codex app-server **6** 次。5 次没有成功确认，包括故障注入和原生身份验证失败；身份验证失败的启动不能推导为发生了模型推理。原生启动中的内部重试不由该计数覆盖。后端报告记录 **0.412543 USD**，另有 **2.8 USD** 保守预约占额（排除结转重复记录）；两者不等同于实际扣费。已完成调用的观测时长约 1.7–134.3 秒，Codex 的长初始化/首响应也计入原生启动时长。

每批次以原子准入上限和绝对截止时间限制；原生响应活动受既有时限控制。真实故障成本继续保守占额，没有通过新后继重置预算。所有验收库的未收敛 Run 和活跃原生进程最终均为 0；用于核对记录的服务随后关闭。

## 适用边界

本次证明冻结阶段图及所选三个后端/模型的适用行为，不扩大到动态 any 竞速、任意嵌套咨询、共享并发写入或未授权信息汇合。窄子范围的跨 Run 迁移继续拒绝，CLI 不具备 R8 所需完整控制能力。严格供应商账单上限、输入成本的全面计量及原生内部请求次数继续属于既有能力限制。重启时的未知调用不自动重放；用户取消与真正失败有不同后续路径。

本轮没有覆盖实体手机、跨主机部署、小时级高负载或所有模型组合，不把这些扩展场景标为通过。Issue #14 是否关闭及代码发布仍需对应远程操作，不随本地报告自动发生。
