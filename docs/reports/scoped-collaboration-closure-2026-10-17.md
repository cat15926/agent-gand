## 结论

普通入口衔接与权限失败后的无效等待已修复。原生本机 all/any、受控发布和进程崩溃矩阵已补齐；真实账户验收部分通过。**G5 仍未全部通过，SDK/Codex 独立材料入口继续关闭。**

## 普通入口与恢复

聊天室输入区增加“本轮如何协作”：普通协作沿用同一授权范围；各成员需要独立材料或选择性发布时，进入“独立材料协作”。

- 普通公开目标可以预填组织目标；已有私密引用、私密输入、附件和用户决策内容不自动带入。
- 逐项材料仍须由 Owner 填写，经过预览、确认后创建新 Run；不复制历史结果或原任务授权。
- 不可重试的权限错误显示展开的恢复卡，“准备独立材料与受控发布”直接打开表单，原任务记录保留。
- 新表单仍使用既有支持矩阵、账户冻结、预算与 Owner 发布授权；SDK/Codex 未因普通账户连接通过而解锁。

桌面及 390px 浏览器验收覆盖公开目标衔接、真实普通任务的拒绝卡、私密内容不预填、刷新、停止、any 和发布入口，页面错误与供应商请求均为 0。

## 不可重试错误与等待

`CollaborationBoundaryError` 将私密转公开、向未获准成员投递，以及私密任务向冻结成员外派发统一收敛为 `PRIVATE_ROUTE_REQUIRES_SCOPE`。恢复说明包含 `retryable=false` 与允许的专用恢复路径。

API 路径不再把该错误作为格式纠偏提示交还模型。原生桥收到拒绝后封闭，返回终止回执、结束客户端并保留实际计量；账户 relay 也在转发前拦截竞态中的后继请求。独立 SDK Scope 最多一个模型回合，仍允许唯一控制工具执行并读取最终用量。普通 SDK 的合法业务工具回合不受该上限影响。

G0 更新后的回归保持 v2 的可见性语义：两种私密越权场景各调用 3 次模型桩，首个拒绝后停止，没有纠偏调用、Hold、问题或恢复派发；公开对照调用 5 次并成功。总计 11 次模型桩、0 网络、0 原生执行。历史 G0 的 17 次调用和 timer/answer 现象仍保留在原报告中；该行为不再是新回归的预期结果。

合法 timer、dependency 与注册事件等待另行回归通过。两个只用于查找的旧测试 fixture 现在取消自己的排队票据，避免阻塞后续同角色 FIFO。

## 验收发现并修复的其他问题

1. **any 提前失败**：一个候选失败时仍可能有其他候选执行。完成快照根据服务端批次事实标注运行中/已成功 any 的可选候选；单个候选失败不提前终结整轮。any 全部失败、超时和必需事项失败仍会失败。未改写原 Dispatch 错误或把失败结果变成可发布结果。
2. **批量控制参数混淆**：组织者提示只展示实际工具参数，不再在要求原样提交的 JSON 内夹带内部 `version/type`。
3. **原生冷目录恢复**：记录 Scope 隔离元数据；确认原进程收敛后，只删除服务端生成且校验通过的冷目录。恢复时不采集祖先 Git 仓库差异；无法验证时保留 attention。
4. **Codex 临时认证握手**：本机 `0.159.2` 要求 `chatgptAuthTokens` 声明实验接口能力。仅隔离 Scope + 临时登录令牌的握手启用该声明，工具/方法白名单、ephemeral、只读及审批检查保持生效。模型和账户权限没有扩大。
5. **超时诊断**：原生账户身份探测有独立的 15 秒时限。现在报告初始化/客户端阶段及实际 15 秒限制，不再误报为 600 秒模型回复超时。独立挂起协议测试确认没有进入 `turn/start`、没有模型调用。
