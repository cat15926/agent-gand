# 编排入口收敛 O5 验收记录

日期：2026-10-06。实现边界见 [O5 架构](../architecture/orchestration-entry-phase-o5.md)。

## 验证环境

真实 React/Vite 页面通过 Playwright 操作；REST 请求交给真实 Fastify 路由，WebSocket 接收真实进程事件总线。使用独立临时 SQLite、角色目录和已提交的临时 Git 仓库，模型调用统一为本地 mock。所有供应商网络请求均被禁止。没有使用用户账户密钥，也没有重置业务数据库。

队列页面使用人工构造的活跃/排队占位来验证显示和操作作用域；真实 FIFO、跨进程互斥与独立成员并发由 O3 回归验证。审批页面使用独立原任务审批卡；真实原生审批/执行绑定和开发评审返工由 O4 fixture 回归验证。O5 页面测试不代替 O7 的真实供应商验收。

## O5 专项结果

`pnpm verify:orchestration-o5`：**11 组通过**，浏览器 React 异常 **0**，真实供应商请求 **0**。

| 验证 | 结果 |
|---|---|
| 空房间 | 零 Run、零派发、零模型请求；重启回填不归档空房间；非法工作区/偏好拒绝 |
| 默认偏好与提交 | CAS 防止覆盖；名称与偏好参与新建提交和幂等摘要；已有任务快照不被默认偏好修改 |
| CLI/SDK 对象 | CLI 不自动切换策略，禁用不兼容工作流；显式只读接力可预览；SDK 自动策略可预览 |
| 草稿、成员与布局 | v1→v2 保留目标、成员、工作区、显式旧偏好；鸡腿选择不改策略/输入框宽度、不调用规划；键盘可用；仅建房保留首轮目标 |
| 固定辩论 | 页面确认后实际执行两位成员 × 两轮，共四次发言；不允许并行去掉依赖 |
| 本轮请求与确认 | 首轮/后续共用新入口；规则预览零模型调用；复杂工作流先确认；编辑失效；发送后恢复默认；主管仅点击详细规划后调用；精确 @ 冲突阻断 |
| 响应丢失 | 浏览器第一次提交响应丢失，重试沿用原 clientRequestId；只创建一个 Run |
| 任务作用域 | 忙碌/队列与前方数量显示；取消 B 不取消 A；安全暂停→预览修订→确认仍暂停→恢复；未知执行禁恢复；审批归属原任务；失败图保留成功输出，不暴露未实现的分支重试 |
| 损坏草稿 | 恢复可识别目标，明确显示损坏提示，原始内容保留可查看 |
| 开发评审 | 绑定独立评审者；未注册工作区阻断；选择注册 Git 工作区使预览失效，重新预览通过 |
| 观察与画布 | 读取实际冻结策略/工作流；聊天建房与任务卡在 390、768、1440 像素无横向溢出；浏览器无 React 异常 |

补充精确提及验证：包含空格的角色名称可识别，中文顿号分隔的提及保持顺序；普通邮箱地址不会被当作目标冲突。
