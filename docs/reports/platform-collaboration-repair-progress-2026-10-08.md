# 平台协作修复进度（2026-10-08，第一批）

更新至 2026-10-09。

对应 [Issue #14](https://github.com/cat15926/agent-gand/issues/14) 和[原始分析报告](./platform-collaboration-gaps-2026-10-08.md)。本次先实施信息边界、超时诊断、保守的只读关联续跑及未知用量展示；不代表六项改进全部完成。

## 已接入的行为

- 新建开放协作 Run 冻结 `messageVisibilityVersion=1`。定向消息默认公开；`agent.handoff` / `agent.consult` 支持 `visibility: "private"`。不带该版本的历史 Run 不下发新增参数，也不承诺私密能力。
- 私密消息的 audience 包含房间所有者和指定成员；消息读取、Context、消息/Attempt/工具/Span 证据、Capsule 及咨询结果回流均检查或继承信息边界。派生汇总只交给发起成员与所有者。上下文内容及可见范围均不可在同一 Attempt 内变更。
- 私密追问继承原消息范围，越权选择成员会返回 `PRIVATE_REPLY_TARGET`；尚不具备逐成员隔离的工作流返回 `PRIVATE_REPLY_UNSUPPORTED`。用户对私密 Hold 的答复也保持私密。私密正式任务提议不能自动转换为共享上下文 Supervisor 任务。
- 新任务不自动引入旧任务信息；聊天室后续消息可携带公开历史，私密旧消息只有显式回复且成员有权限时才带入。同一成员处理公开任务时，也不能带入该成员其他私密事项；多成员上下文只能带入所有接收成员共同获准的信息。原生会话按 Run、可见性和 audience 绑定，跨 Run 或信息边界变化建立新会话。
- 私密回合关闭普通业务工具和原生文件工具，仅保留文本与 Runtime 控制；私密文件产物尚无独立 ACL，含私密消息的 Run 不将未绑定来源的文件证据提供给 Agent。当前所有者仍能查看完整房间审计记录；这是单用户产品的 Agent 信息隔离，并非多租户访问控制。
- 排队、平台工作区准备与模型执行分开计时。外部执行不再被外层全局默认时限提前截断；采用所选账户冻结连接中的时限，并与运行截止时间、固定步骤租约取最早期限。有效值、来源、排队时间、会话建立、首正文和首工具时间写入执行记录。
- 超时区分初始化、会话未建立、已建会话但无正文/工具活动、活动后未完成及截止时间。RPC 超时保留有界、脱敏后的 stderr；MCP 执行桥保留 HTTP 拒绝的校验原因。
- 已接收有效协作控制候选而停止原生回合时，缺少原生控制工具结束事件记录为 `control_interruption`，同时标记 `tool.completion_observed=false`。这表示受控停止，最终动作提交仍以 Runtime 账本为准。普通工具缺少结束事件仍保留异常，不据此推断副作用已完成。
- 预算面板展示已知消耗、未知 Token/成本调用数量及进行中的原生调用。未知调用不会被显示为零成本；现有金额阈值仍只约束已报告的成本，尚不是对未知用量的硬支出保证。
- 新增公共恢复资格检查及失败任务卡的“预览只读续跑 → 查看待续事项与已确认输出 → 确认并续跑”。对单个明确失败事项、已冻结信息边界的公开只读自由协作，创建唯一的关联 Run，重新冻结当前账户与角色，只派发待续目标。旧终态、消息、Attempt、执行证据保持不变；确认输出由不可变 manifest 引用并注入 Context，平台不重新调度旧 Dispatch。相同成员的相同已完成目标再次被交接/咨询时会被阻止；语义改写的重复工作尚需业务阶段契约约束。
- 续跑资格阻断未知/仍活跃的进程及工具结果、原生写入与非 safe 工具操作、私密状态、历史未声明信息边界的 Run、并行失败/未结束分支、无法分类的错误及其他引擎。其他引擎已有的暂停恢复与分支重试保持原入口。当前续跑是只读文本进度承接，不承诺工作树迁移、私密状态恢复或跨引擎一致续跑。
- SQLite 新字段有默认值，历史消息继续按原有公开语义解释。以前没有声明私密的身份牌不会被自动重新分类；验收私密流程应创建新任务，并明确使用私密投递。

## 使用示例

为不同成员发送不同私密信息时，应分别发起咨询；同一私密咨询的多个 targets 会共享同一个问题及授权范围。

```json
{"targets":["player-a"],"objective":"你的身份信息……","reason":"单独确认","visibility":"private"}
```

Agent 收到私密来源后的回复与汇总自动继承范围。后续交接/咨询也只能指向已有读取权限的成员；即使再次声明 `private`，也不能把带有其他成员秘密的上下文投递给新成员。若要发布公开内容或扩大成员范围，所有者应新建明确的任务并提供已获授权的摘要；当前不允许 Agent 自动扩大私密来源的授权范围。多轮不同私密问题的自动编排需要后续差异化任务与独立上下文能力，不能用普通串行咨询绕过边界。

## 验证状态

已通过类型检查、`verify:message-visibility`、`verify:execution-diagnostics`、`verify:run-continuation`，以及现有 Context、Agent API、ControlAction、EvidenceBundle、consult(any)、Durable Hold、Completion、原子终局和公共动作命令验证。

新增可见性测试覆盖两名成员的不同私密信息、公开定向兼容、根目标遮蔽、越权证据/Capsule、实际聚合函数、上下文/幂等 ACL 漂移、原生会话边界重置、排队超时和未知预算计数。诊断测试使用本机模拟 stdio 进程，验证期限裁剪、阶段分类、stderr 脱敏及进程清理，不调用供应商模型。

续跑验证使用临时数据库，无模型调用及回环监听：验证规则预览不创建 Run、重复提交唯一关联、原记录完全不可变、已确认输出与待续目标进入 Context、相同目标路由阻断、未知/私密/写入围栏、配置变更拒绝及入口关闭策略；用 Fastify 注入验证恢复查询、任务状态和缺少确认时的 HTTP 拒绝。完整 native/UI 端到端续跑未计为通过。

SDK/Codex 混合 MCP 夹具已增加私密咨询、汇总、越权追问、后续公开任务及控制中断断言，完整复跑仍待完成：此前交接场景出现一次等待超时；随后两次自动审批超时，沙箱复跑因回环监听 EPERM 失败。聊天室浏览器回归也因沙箱无法验证服务进程身份而未完成。这些检查未计为通过，正在请求允许本地夹具测试。
