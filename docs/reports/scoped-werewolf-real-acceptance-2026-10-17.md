## 格式恢复与信息边界

第一次本地启动因随机端口未在初始化时纳入管理 Host 白名单而停止，供应商请求 **0**；已调整为先选定端口，再初始化服务。

实际首夜模型返回了 `{"action":{...},"statement":{...}}`，严格解析器先以 `GAME_ACTION_INVALID` 停止。之后增加有限兼容：校验包装层、内部行动和可选声明字段，仅消费夜间 `action`，提前声明保持私密并丢弃，不作为后续公开声明。原始输出保留，原 Run 直接复用，没有重发首夜请求、改变目标或重抽身份。`resumptions` 留有记录；次数、Token 及总时限沿用原账本。后续玩家材料也明确要求只提交当前阶段对象。

- 12 个实际 Attempt 均有 Scope 绑定。

- 按产品可见性函数检查各玩家可见消息，其他玩家私密标记命中数 0；公开消息私密标记命中数 0。
- 首夜重复发布返回同一结果，落库仅 1 条发布记录；停止后活动 Run 和活动模型调用均为 0。

## 后续与复现

本轮暴露两项工作：第一，结构化行动需要明确的阶段格式及兼容边界；第二，独立协作的供应商错误被折叠为通用错误，Owner 缺少安全的超时分类与活动时间证据。下一次真实复验应先补充这些诊断，再在明确预算下使用更接近日常账户的时限；保留未知调用占额，不改账本伪装成功。

新增脚本：

```sh
pnpm verify:scoped-werewolf-rules
# 默认只读检查选定账户，不发送推理请求。
pnpm scoped:werewolf-real --account <managed-account-id>
# 明确执行时使用全新隔离目录；会产生真实调用。
pnpm scoped:werewolf-real --account <managed-account-id> --output-dir <new-isolated-dir> --execute
```
