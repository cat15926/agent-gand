# 平台协作剩余计划 R7 验收记录（2026-10-12）

R7 已交付适用范围内的差异化阶段批量任务、即时补位调度、授权汇合、确定性状态迁移及调用/预算等待可视化。生效契约见[差异化阶段批量调度 v1](../architecture/scoped-stage-batch-scheduling-v1.md)。R6 基线为 `bcc6cde184ba55b8bfd861a070bcd581558c4cc9`；R7/R8 提交及发布状态以 Git 历史为准。本记录保留 R7 阶段的验收结果，后续真实验收见 [R8 记录](platform-collaboration-r8-acceptance-2026-10-13.md)，Issue #14 的远程状态另行确认。

## 交付

- 业务契约 schema v3：每名成员的目标、依赖和范围；1–8 并发声明与服务端冻结上限；独立成员的显式输入汇合和全部成员完成条件。
- 不同私密分工只向获准成员提供对应目标、正文、文件和证据。拒绝越权依赖及更宽输出；不拼接未选择的汇合输入。混合范围批次的公开成员也不能借网络/原生工具绕过隔离。
- 依赖就绪后立即补位，慢独立分支不阻塞其他已就绪下游；写入顺序，失败停止未领取事项，暂停/取消不继续派发。API 及原生预算队列保留可恢复票据，不误记为已调用结束。
- 平台派发回执、门禁和终态继续持久化处理；Owner 验收独立，纯“收到”不能被当作实质交付。公开阶段部分返工会重做受影响成员和汇合，保留其他可信结果。
- API 请求及原生启动账本、准入排队时间/原因、Owner 运行面板和最少调用规模预览。区分 Span、回执、实际 provider 调用、原生启动和客户端内部未知请求。
- 追加迁移 v11，旧 worker 拒绝忽略新语义；保留旧契约、原预算、费用未知政策及唯一后继。

## 调用规模对照

临时夹具实际运行原 Collaboration `consult(all)` 的两成员分析与汇合路径，再运行 Owner 明确分工的 v3 阶段：前者记录 **5 次模型调用**，后者 **3 次**（两名成员各一次、汇合一次）。新阶段的派发回执、Owner 验收、两个平台门禁及终态没有新增模型请求，模型没有被用于确认状态。

这是模拟控制流程的对照，不是实际模型质量、供应商计费或长任务性能基准，不能据此承诺所有任务减少 40% 费用或耗时。该夹具同时记录 A 完成后 C 在慢 B 结束前启动，以及汇合晚于所有必要分支结束。

## 边界

批量机制属于已冻结的逐阶段图；不扩展成动态 any 竞速、任意嵌套咨询或不受约束的共享写入。窄私密状态支持同 Run 安全暂停恢复，跨 Run 检查点仍明确拒绝，不自动合并授权。共用 Run 范围的私密写入恢复继续走 R4。

原生启动不等于客户端内部所有推理请求，账本也不是供应商发票。SDK 初始化或崩溃的费用无法证明免费时继续保守占额；API 输出预算不覆盖全部输入计费。预算行为和严格账单拒绝沿用 R5。

旧 O5 浏览器脚本仍需适配之前的抽屉交互，本轮未宣称整个旧 O5 UI 套件通过；当前 R7 浏览器专项及 O6 冻结图回归有独立通过记录。实际 Claude SDK、Codex、模型 API 混合长链路、真实网络故障及供应商费用真实性仍由 R8 验收。
