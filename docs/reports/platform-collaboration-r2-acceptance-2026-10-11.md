# 平台协作剩余计划 R2 验收记录（2026-10-11）

对应[实施计划](../plans/platform-collaboration-remaining-implementation-plan.md)和[生效权限契约](../architecture/private-interaction-artifact-acl-v1.md)。R2 已完成本地实现与适用范围验收；R3–R8 保持待实施。提交与推送状态以 Git 历史为准。

## 已交付

- 用户输入可选择公开/私密、获准成员及附件；执行成员与范围分开选择。桌面及手机预览抽屉显示“谁能看到”、文件范围与确认按钮。引用、草稿恢复、图修订和自动选人保持授权边界。
- 受控文件按来源、版本、ACL、哈希和创建时验收账本版本保存；附件与 Run 原子提交，重复确认不会重复创建文件。内容加密，元数据参与认证；私密字节不会进入原生工作目录。
- 下载、平台读取/搜索、证据、上下文、步骤依赖、汇总、旧 Run 私密子任务过程消息和原生会话检查同一信息边界。只有获准成员身份仍不足以将窄范围文件带进公开或更宽的任务。
- Collaboration 与 Coordination 支持适用的私密模型 API、Claude SDK/Codex 只读成员；CLI、共享上下文引擎、外部原生私密写入在预览拒绝。附件要求开放受控文件读取工具。
- 所有者可以下载具体版本，填写范围与原因扩大文件授权；新版本与审计一起保存，旧版本和已绑定证据不会自动公开。
- 追加迁移 v6；保留私密恢复围栏，并为尚未接入归档的公开受控文件任务增加明确阻断原因。完整产物/Git 快照及私密、写入恢复分别留给 R3/R4。

## 验收边界

没有使用真实 Claude/GLM/Codex 账户，不能把模拟驱动通过写成真实供应商长链路通过。步骤图范围和依赖证据已用模型 API 夹具验证；两种原生驱动新增文件场景通过 Collaboration 验证，不宣称逐一覆盖所有原生步骤图工作流组合。

新附件限制为每轮 4 个、单个 256 KiB；模型读工具按 UTF-8 文本工作。文件完整归档、仓库改动恢复、附件图修订、私密原生写入和跨 Run 私密恢复尚未开放。受控文件保存版本不代表其已通过业务验收。

下一阶段为 R3：把受控文件版本纳入完整声明产物清单和可验证检查点，补齐 Git 基线、工作树变化及恢复路径，再进入 R4 私密/写入续跑。

后续更新：上述归档缺口现由 [R3](./platform-collaboration-r3-acceptance-2026-10-11.md)交付。本报告保留 R2 当时的验证范围；当前公开逐阶段受控文件检查点已开放，私密/写入自动恢复和跨引擎承接继续由 R4/R6 跟踪。
