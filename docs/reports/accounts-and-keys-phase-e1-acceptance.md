后续状态：E2–E4 本地实现与验收已完成，真实供应商验收仍待用户完成，见 [E4 记录](./accounts-phase-e4-acceptance.md)。本文描述 E1 交付时的证据与边界。

## 交付范围

- 新增独立“账户与密钥”页面、API Key 表单、搜索/筛选、连接编辑、换钥/清除、启停、引用详情和删除/归档。
- 新增共享账户契约、版本化 SQLite 存储、AES-256-GCM 凭据加密和脱敏 API。
- 旧环境及原生认证来源只读展示，分别记录内置 Anthropic 和 Claude SDK 来源。
- 管理接口采用本地会话、Host/Origin 校验、CSRF 和远程口令门控；默认服务监听改为 loopback。
- 私有文件在平台文件工具、搜索、工作区注册及复制中受保护；已有外部审批、工作区隔离和恢复行为继续保留。

现有角色未迁移，模型调用仍使用旧认证路径。API 和页面均说明托管账户暂未绑定运行。没有调用真实供应商、读取供应商账户身份或完成新登录流程。

[账户验证脚本](../../scripts/verify-accounts-e1.mjs)使用临时数据库和伪 Key，启动独立服务器，结束后清理。关键断言包括：

1. 同供应商多个密钥分别保存/解密，轮换不覆盖旧版本，改名不改变连接版本，过期修改返回 409。
2. 数据库文件、API 响应和测试日志不包含伪 Key 原值；格式错误也不返回原请求内容。
3. 私有目录 `0700`、主密钥文件 `0600`；服务重启后可解密；主密钥丢失不重新生成；篡改认证 tag 显示无法解密。
4. 停用角色仍阻止删除；活动 Run 阻止删除；历史 Run 或历史角色版本使账户归档；归档清理凭据并保留配置。
5. 无会话、错误 CSRF、恶意 Origin/Host、跨站建立会话均被拒绝；远程监听缺口令拒绝开放，错误口令被拒绝，合法口令通过。
6. 私有文件、符号链接别名不能被文件工具读取/搜索或作为工作区注册；Chat Completions 网关不被标记为 Codex 兼容。

测试中插入的未来 `accountRef` 和 Run 绑定只存在于临时数据库，不为本地用户数据制造历史绑定。
