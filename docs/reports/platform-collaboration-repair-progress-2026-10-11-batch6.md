# 平台协作修复进度：第六批（2026-10-11）

对应 [Issue #14](https://github.com/cat15926/agent-gand/issues/14)。承接第五批阶段续跑，这一批补齐公开只读阶段交付被拒绝后的明确返工入口。

## 已完成

- 阶段拒绝后填写修订要求，预览全部返工成员任务、保留阶段、文件范围、时限和预算，再确认执行；拒绝、登记候选和预览本身不会重跑模型。
- 创建关联新 Run，继承已验收阶段，仅被拒绝阶段重新调用成员；原分工及验收标准冻结，后续阶段仍须等待本次验收。
- 独立归档拒绝原因、修订要求及旧候选。旧候选只供分析问题，不能作为新任务的交付证据；新任务必须重新登记本轮输出。
- 新 Run、检查点、预算结转、后继关系和原等待执行关闭原子提交。失败确认不取消原任务；关闭失败整体回滚，事件不提前发布。已失败原任务不重写终态，原验收记录封存。
- 连续返工结转原 Run/阶段输出预算，不通过新任务重置额度。返工中途失败后，阶段续跑保留修订要求及拒绝归档，并跳过已经完成的返工步骤。
- 沿用 Owner 管理认证、CSRF、Host/Origin、版本与指纹校验。配置或验收变化要求重新预览。私密、写入、未知消耗/副作用、已取消、非拒绝实质交付等明确阻断。
- 实际手机复核发现聊天“跳到最新”会遮挡预览底部操作区，已改为消息区底部独立导航栏，并加入确认按钮与导航按钮不相交检查。
- 编排迁移追加 v5，旧 worker 拒绝忽略返工契约。

契约与交互见[公开只读阶段返工 v1](../architecture/business-stage-rework-v1.md)。

## 验证

返工专项 execute/off 夹具通过，包括连续返工预算上限、旧候选不可验收、配置/说明/验收漂移、无孤儿 Run、原执行关闭失败整体回滚、原账本不变、返工失败续跑、冷进程读取、Owner HTTP 和幂等。

阶段门禁 execute/off 夹具使用实际 Claude SDK/Codex 驱动与本地 stdio 模拟进程，分别验证 SDK 已验收后返工 Codex、Codex 已验收后返工 SDK；conversation 策略建立新的绑定及冷会话，API 后续阶段最终验收达成。

实际 Chrome 桌面与 390px 操作拒绝、必填要求、预览关闭/修改、确认返工、查看修订来源、只选择新交付、继承前置阶段和重新验收至达成；页面、API 与 WS 事件来自内存夹具，无监听端口或真实模型请求。截图和测量在忽略目录 `apps/server/data/business-stage-ui-qa`。

类型检查、Web 构建、阶段续跑、业务验收、普通只读续跑、O1、聊天滚动控制器与文档链接检查通过。独立消息导航通过实际 UI 验证：不遮挡确认按钮，新消息不抢阅读位置，点击后回到最新并关闭导航。Web 保留现有大 chunk 构建提示。

## 剩余范围

1. 私密/写入阶段返工、选择部分成员返工或修改验收清单；多分支/跨引擎检查点、写入工作树和完整仓库基线迁移。
2. 未知货币成本的保留额度与费用硬预算、文件 ACL、完整产物归档。
3. 更完整的失败因果链和混合引擎故障联合测试；真实 HTTP/WS 网络链路及经授权的真实供应商验收。早前本地监听 Runtime C 夹具仍待单独解决，不将本批 stdio 模拟通过视为该项验收。
