# 聊天室 UI 优化实施与验收

日期：2026-10-07。依据：[聊天室 UI/UX 审查报告](chatroom-ui-ux-audit-2026-10-07.md)。按报告的三批顺序实施，验收覆盖实际本地业务页面与独立测试环境。

## 实施结果

| 顺序 | 项目 | 已实现的交互 |
| --- | --- | --- |
| 第一批 | U01 消息完整性 | 查看任意轮次仅切换任务详情；保持当前历史页、引用和正在运行的其他任务的流式内容。全房间历史保存在服务端，可以前后翻页。过期详情请求不覆盖当前所选任务。 |
| 第一批 | U07 刷新与阅读位置 | URL 保存房间与任务；浏览器本地保存最近房间；每个房间在当前标签页保存阅读锚点。刷新与浏览器返回恢复上下文。 |
| 第一批 | U08 任务上下文 | 详情明确标注“第 N 轮 · 当前查看的任务”；调度、尝试、轨迹、预算、审批与用量按该任务过滤，房间整体调度单独标注。 |
| 第二批 | U02 输入区 | 默认只显示目标、接收人摘要、执行设置入口与发送/预览。输入框自动增高并限制最大高度，手机发送控件保持可见；计划详情可以收起，确认按钮与错误提示保持可达。工作流、策略、辅助角色、约束、工作区与默认偏好移入设置抽屉。 |
| 第二批 | U03 手机布局 | 手机使用顶部导航与覆盖式房间列表；打开列表不改变聊天区宽度。 |
| 第二批 | U04 详情可达性 | 各宽度均有任务详情入口，按需打开抽屉；取消 1280px 断点自动占用/释放 320px 的行为。 |
| 第二批 | U05 成员与接收人 | 建房显示“房间成员”，说明候选成员不等于每轮执行者；接收人支持明确勾选、头像、可用/忙碌/排队状态、角色与接入信息提示、@补全及冲突提示。选择 SDK 成员不改变策略。常用执行方式预设映射现有编排配置。 |
| 第二批 | U06 失败恢复 | 任务卡显示可执行的处理建议与可展开的错误原文；普通失败可准备新任务草稿，工作区失败可带入新房间重新配置。草稿保留目标、成员、接收人与设置，不直接重试，已确认结果继续保留。 |
| 第二批 | U09 操作入口 | 明确的房间菜单包含重命名、设置、归档；归档继续要求确认。列表提供显式重命名、保存/取消及错误反馈。手机回复、复制与审批操作扩大触控区域。 |
| 第三批 | U10 信息层级 | 已完成任务默认紧凑显示，计划细节按需展开；审批、问题与失败提示保留内联入口。原生执行、工作区、快照及证据移入任务详情，技术审计默认折叠。 |
| 第三批 | U11 视觉与术语 | 聊天与详情元信息采用更清楚的灰度和字号；常用调度/执行状态及轨迹标签中文化；未知成本与未完整报告的用量明确说明。 |
| 第三批 | U12 阅读控制 | 手动查看历史时保持位置；新消息显示计数并提供“跳到最新”；引用与搜索结果跳转时高亮消息。 |
| 第三批 | U13 长内容 | 长报告可展开/收起并按目录跳转；代码块提供复制与反馈，表格/代码保持局部横向滚动；支持全房间消息搜索、跨页引用定位和独立成果列表；成果与详情均可访问已有变更补丁。消息按稳定序号分页，每次 80 条，页面最多保留 160 条。 |
| 第三批 | U14 加载与键盘 | 初始加载、加载失败、空房间分开显示，失败可以重试。原生模态抽屉提供背景隔离、焦点约束、Escape 关闭及焦点恢复。可选择 Enter 或 Ctrl/⌘+Enter 发送，保留 IME 输入保护和 Shift+Enter 换行。 |

预览确认、独立评审、账户绑定、角色权限、任务安全暂停/恢复/修订继续使用原有后端接口与约束。输入区重新组织未引入新的执行模式。

## 预期操作路径

1. 新建聊天室，选择房间成员与可选名称。
2. 描述任务；不选择接收人时自动选择，或通过接收人按钮/@提及明确指定。
3. 需要修改执行方式时打开“执行设置”，选择预设或调整策略、工作流与约束。
4. 发送或预览；需要确认的计划仍须确认后执行。
5. 查看任务详情时保持当前历史页。更早和后续消息可以按页加载，搜索、引用和成果定位会加载目标所在页面。审批和 Agent 问题在对应任务中直接处理，历史页外的待处理决定继续显示入口。
6. 失败后按提示检查配置，再准备新任务草稿；修改工作区需要创建新房间。

## 验收

### 自动回归

- `pnpm verify:chat-state`：多轮消息与流式内容保留、所选任务不被其他运行更新抢走、过期请求隔离、跨房间清理、@最长匹配及同名处理、断线后的终态流式清理。
- `pnpm verify:chat-scroll`：异步回填、手动阅读、恢复锚点前的加载保护、跳到最新与阅读状态保存。
- `pnpm verify:chatroom-ui`：隔离数据库、模拟模型与原生客户端，覆盖加载失败重试、浏览器返回、查看旧任务、刷新、消息搜索、报告目录与代码复制、快捷键、SDK 接收人、重命名、六种宽度、失败草稿、手机审批与问题、新建房间发送，以及既有 O7 浏览器用例。
- `pnpm verify:chat-history`：5,000 条历史加待处理问题，覆盖正反向游标、跨房间隔离、错误参数、字面全文搜索、成果分页、160 条窗口上限、重复投递/新消息计数、REST 与 WebSocket 回填竞态、跨页引用与提问、刷新阅读锚点、引用任务文案、输入增高、折叠计划与模拟软键盘。模型调用为 0。
- `pnpm verify:accounts-e3-ui`：已有账户/角色向导、Codex 登录与保存启用、加入建房草稿、损坏草稿恢复及手机布局回归。
- 全项目类型检查、前端生产构建、文档链接校验。

浏览器脚本需要 `PLAYWRIGHT_MODULE` 与 `CHROMIUM_EXECUTABLE_PATH` 指向本地已安装的 Playwright 和 Chromium；不需要真实模型账户。供应商请求为 0。

## 剩余优化补齐

已补齐此前按需延后的历史加载与成果入口，以及输入区的交互细节：

- 服务端增加历史游标与定位接口，聊天室不再一次下载所有消息。执行器读取完整上下文的路径保持原有行为。
- 页面最多保留 160 条消息；加载更早/后续消息保留阅读锚点。实时消息与历史分页分别计数，翻页不会被当作未读；浏览旧页时不插入远端消息制造历史缺口。
- 搜索覆盖整个房间，按 30 条匹配分页；引用和成果定位可以跨越当前页。成果列表按页展示任务结果、协作结果和审查结论，选中编码任务可以下载现有补丁。
- 当前页与尚未结束的任务继续保留任务卡、审批和问题入口。任务状态与协作明细仅加载当前历史页、所选任务及尚未结束的任务，避免每两秒读取整个房间的执行明细。
- 普通引用明确显示“引用并新建任务 / 发送引用任务”；待回答问题保持原任务续接，安全修订保持暂停。
- 输入框随内容及宽度变化自动增高；手机控制区触控高度至少 44px。可见视口发生软键盘变化时，输入区与抽屉跟随可见高度。长报告目录定位会先展开正文。

隔离长历史测试的网络记录显示，每次历史响应为 80 条，房间与任务明细响应不包含全量消息；浏览器错误为 0、真实供应商请求为 0。测试缓存目录独立，避免多个浏览器验收服务共享开发缓存。

新增证据位于本地忽略目录 `apps/server/data/chat-history-qa/`，包含请求数量记录和模拟软键盘截图。软键盘测试模拟 460px 可见视口，发送按钮底部为 440px，设置抽屉高度不超过 460px。

报告中的功能优化已完成。真实 iOS/Android 软键盘的设备体验仍需用户验收；自动化模拟不能替代真实设备结论。
