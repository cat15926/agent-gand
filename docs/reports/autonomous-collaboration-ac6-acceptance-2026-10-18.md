## 后续优化与真实复验

用户再次授权继续真实验收后，修复问题并以新隔离根取证，未改写旧失败根或补造玩家行动。

1. **SDK 回合耗时**：原 Claude Code 通用编码 preset 混入每次冷启动的控制任务。改为平台完整任务提示词、SDK low effort，并传入冻结的单次输出预算。角色原始说明、模型、账户和权限保持。一次 SDK 负责人完整委派→API 核对→SDK 自汇总→交付已用约68秒完成；这是该组合本次观测，不是对所有模型的时延保证。
2. **成员与文件委派参数歧义**：模型曾用 `self` 作为成员 ID，或省略输入句柄/文件工具、把结果可见范围当收件人。每个回合的 schema 现在枚举真实成员/材料 ID，文件委派显式填写 inputIds 和 allowedTools，并解释 outputAudience 必须包括执行成员。不同 Scope 不共享可变 schema，服务端仍逐项验权，不替模型改写被拒绝请求。
3. **流程编号歧义**：真实主持曾把当前 step=2 填为3。推进工具现在只提供当前 flowId/expectedStep，明确其用于当前状态校验；初始工具与推进工具分别提供相应字段。玩家决策、目标和规则裁定仍由真实模型与规则引擎分别负责。
4. **文件快照缺少版本标识**：旧任务的读取只看到冻结 v1，原汇总上下文却将多个材料正文直接拼接，模型误判新版本未保存并反复返工。AC6 的材料上下文、文件句柄目录和 fs.read 回执增加确切路径/版本/产物 ID/SHA-256；说明旧句柄不自动升级，复核应通过 aggregate 读取实际新产物。此变更不读取范围外的新版本，不覆盖旧版，不升级旧根上下文。
5. **验收完整性**：真实脚本运行生产同样的续租和持久等待恢复；新增文件场景、唯一最终交付、运行时审计、模型终态、实际产物读取/写入与复核来源校验。游戏需重算完整状态链，核对每次玩家行动有真实 SDK 执行，并核对私密材料仅流入对应玩家。默认参数仍为单次回复600秒、根输出48000、单次请求12288，Codex 跳过。
