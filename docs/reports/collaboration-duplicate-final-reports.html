③ 三层根因

R1 · 内容双投递（放大器）

batch 子任务用 handoff 回发起者时，正文走两条路：handoff 自建一条 dispatch，maybeCompleteBatch 又把同一段全文塞进 aggregate 再建一条。reviewer 每条调研各收 两份。

R2 · finish 不清队，完成后照跑（直接原因）

每条 dispatch 独立成回合，finish 只发消息不清队；executeDispatch 不检查 run 状态——02:42:31 run 已 completed，#2、#5 照样各跑一回合、各发一份完整汇总。

R3 · 窄上下文误判 + 话术催促（导火索）

处理 #1 时"当前事项"只有 jitui 单条（transcript 每条截 2000 字符），reviewer 没认出 aggregate 里已有国内线，重发征询；乒乓提醒硬编码"辩论轮次"话术，推动 nim 二次提交，凭空多出 #5。

④ 修复方案（按性价比排序）

  1. 必修executeDispatch 前置检查 run 状态：run 已 completed/failed → 跳过剩余 dispatch（标记 cancelled + 留痕说明）。
  2. 必修finish 时取消同 run 其余 queued dispatch：汇总者明确收尾后，迟到的重复材料不再各触发一回合。
  3. 建议batch 子任务 handoff 回发起者去重：结果已由 aggregate 投递，handoff 消息可保留展示但不再进调度队列。
  4. 建议乒乓提醒文案中性化：非辩论任务不再出现"辩论轮次"字样。
  5. 长期回合前队列合并：同一 target 多条 queued dispatch 内容高度重复时合并执行。
