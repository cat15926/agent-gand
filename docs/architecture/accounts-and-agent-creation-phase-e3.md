# 阶段 E3：选择账户的三步角色向导

状态：E3 实现完成。日期：2026-10-05。接入与认证沿用 [E2](./accounts-and-keys-phase-e2.md)，加密及管理边界沿用 [E1](./accounts-and-keys-phase-e1.md)。本阶段验证证据见 [E3 验收记录](../reports/accounts-and-agent-creation-phase-e3-acceptance.md)。真实供应商授权和模型权限留待实际账户验收。

## 使用流程

在“舰队 → 角色管理”点击“创建角色”。已有未保存草稿会恢复；“新建空白角色”开始新的创建草稿。编辑、复制也使用同一向导，文件角色继续只读，可复制为数据库角色。

### 1. 角色职责

选择通用助手、规划主管、编码执行者、代码评审者或自定义模板，填写名称和一句话职责。模板提供系统提示词、能力和权限，可展开修改。规划主管使用模型 API；外部 Code Agent 不承担平台协调角色。

角色 ID 根据名称生成，在“身份高级设置”可修改；手动修改后不再自动覆盖。编辑已有角色时 ID 固定，复制时生成新的 ID。服务端返回重复 ID 等错误后保留草稿并回到对应字段。

头像可使用 Emoji、文字、URL，或选择、拖入小于 5 MB 的图片。文件在保存角色时上传；打开账户子面板、返回及关闭后再次打开向导会保留本次选中的文件。

### 2. 接入与模型

用户选择“模型 API”“Claude Code”“Codex”或“演示”，再选择账户及原生模型 ID。表单自动生成内置模型的 `anthropic:` / `openai:` 前缀；外部客户端保存原生 ID，演示使用 `mock:`。

| 接入方式 | 可选账户 | 默认执行方式 |
| --- | --- | --- |
| 模型 API | Anthropic Messages 或 OpenAI Chat Completions 的 API Key | 相应内置 Provider |
| Claude Code | Messages API Key；Claude 原生登录身份 | API Key 使用 SDK；原生登录使用只读 CLI |
| Codex | OpenAI Responses API Key；Codex 原生登录身份 | app-server；高级设置可选择只读 exec |
| 演示 | 无需账户 | 本地 MockProvider |

候选按账户声明的协议和 Driver 兼容性过滤。仅支持 Chat Completions 的网关不会成为 Codex 候选。候选兼容不代表模型权限或真实服务已验证。

新建角色只有一个可用的托管账户时自动选中；有多个时要求选择。停用、待登录等条目仍可用于草稿，并显示需要修复的原因。已有角色的绑定即使停用、撤销或不可见，也会保留原 ID，不能自动替换为另一账户。

“新增”就地打开统一账户表单，预填当前产品。创建兼容账户后回填选择；原生账户创建后进入登录面板。“管理”打开完整账户列表，返回时职责、提示词、模型、权限和头像草稿保留。账户变更通过 WS 刷新。

模型候选来自账户维护的目录和推荐模型，也可输入自定义 ID。原生登录可使用客户端默认模型 `default`；没有自动供应商模型发现。切换接入产品会保存各产品的连接和权限草稿，切回时恢复，并重新应用当前载体的限制。

驱动 ID、模型 API 协议选择和原生会话策略位于高级设置。新建 SDK/app-server 角色默认同一 Run 复用；只读 CLI 使用每回合会话。编辑旧角色时保留其已有会话语义。

### 3. 权限与确认

提供“只读分析”“写入需确认”“按白名单执行”。通用助手和评审模板默认只读；编码执行者默认确认模式，写入和命令工具未预先加入免审列表。明确禁用的工具优先于允许列表。

“实际权限预览”来自服务端，展示当前模式、原生免审工具、可执行平台工具、平台免审工具、明确禁用工具、会话及运行限制。常用权限在主界面，工具细节和能力在高级设置。底部固定摘要显示职责、产品、账户、模型和权限。

载体约束继续生效：

- Claude SDK 确认模式的 Read/Grep/Glob 免审，其他未勾选原生工具逐次确认。
- Claude CLI / Codex exec 强制只读，清除平台工具桥接，只供顺序流水线的只读分析。
- Codex app-server 不提供平台“按白名单执行”模式；托管 Codex 拒绝可能脱离沙箱的原生命令审批，工作区文件修改可审批。
- 外部 SDK/app-server 的 Runtime 协作控制工具由平台提供；账户选择不能扩大工作区范围或绕过审批。

点击“测试连接”会预填当前后端和模型，只有点击发送测试请求才调用模型，可能消耗额度。测试结果必须匹配相同后端、模型和当前连接版本，不能将其他模型通过显示为当前角色已通过。

“保存角色”做一次最新预检；认证已配置、尚未测试的模型也可保存。预检不证明供应商支持该模型。“保存为停用草稿”允许账户尚未选择、未登录、停用、不兼容或客户端缺失，但仍执行角色结构和权限校验。两种保存都保留版本冲突保护。

保存可用角色后可点击“加入建房草稿”：合并到运行页的新聊天室成员选择，并保留原建房目标及其他成员，不创建聊天室、不发送消息、不修改已有聊天室。停用草稿提示修复连接后启用。

## 服务端契约

`AgentSaveInput` 支持可选 `enabled`，默认创建启用角色，更新时未传则保留当前状态。停用草稿的定义和状态在同一数据库事务保存；启用、启用状态下修改及显式账户的新建均检查当前账户。账户在预检后改变状态时，写入事务再次检查绑定。

新向导非演示角色设置 `requiresAccount: true`。即使草稿暂时没有 `accountRef`，解析器也会明确拒绝，禁止误用旧环境凭据。旧角色、文件定义、旧快照未设置该标记时继续原兼容路径；编辑和复制保持其原绑定，用户可显式改选托管账户。无需数据表迁移。

`POST /api/agents/preflight` 接受完整 `AgentInput`：

```json
{
  "ok": false,
  "issues": { "accountRef": "请配置账户认证" },
  "testedModel": false,
  "permissions": {
    "summary": "只读分析；禁止写入和有副作用的命令",
    "nativeTools": [],
    "platformTools": ["fs.read"],
    "allowedTools": ["fs.read"],
    "deniedTools": [],
    "session": "每回合新会话",
    "limits": ["工具仍受工作区范围与审批策略约束"]
  }
}
```

结构及工具策略错误仍返回 HTTP 400；账户兼容、认证或客户端不可用返回 HTTP 200、`ok:false` 和字段问题，便于展示权限并保存停用草稿。接口不调用模型，不返回密钥或认证目录。实际保存/启用遇到不可用连接返回冲突，不能仅依赖前端按钮禁用。

## 草稿与可访问性

角色草稿保存在当前标签页 `sessionStorage`，按创建或编辑 ID 区分；编辑草稿仅在基础版本仍相同时恢复。保存内容包括角色字段、账户 ID、模型、权限、步骤及各接入产品草稿，不包括 API Key、管理令牌或登录秘密。恢复时校验连接字段、工具列表、能力、执行载体和会话枚举，只恢复已知字段；主体损坏时忽略草稿，各产品缓存损坏时仅忽略对应缓存，保留有效的当前角色。保存成功清除草稿，浏览器存储不可用时仍可使用内存表单。

完整刷新或离开导致组件卸载时，未上传图片文件不能从浏览器存储恢复；恢复提示要求重新选择头像。已保存头像不受影响。建房草稿另行保存目标、成员、模式、主管、评审者和工作区，恢复时校验所有字段及成员/发送对象列表，创建聊天室成功后清除。

向导与账户子面板支持焦点约束、Escape、焦点恢复、字段标签和错误提示。切换步骤聚焦当前步骤，服务端字段错误回到可见字段并聚焦；只读 CLI 的权限不可修改时聚焦实际权限预览。子面板打开时父向导不可交互；嵌套面板 Escape 只关闭当前面板。窄屏内容可滚动，摘要和保存操作保持可见。

原生会话复用策略在服务端实际权限摘要中显示，修改高级选项后重新预检并更新摘要。建房页收起运行详情，小屏默认折叠聊天室列表，为任务输入和成员选择保留空间；选择已有聊天室后仍显示运行详情。

建房页的协作方式由用户显式选择，成员增减不会自动切换为流水线。新建智能匹配草稿默认选择模型 API 成员；恢复已有草稿时保留原成员和模式。舰队成员独立成组、显示选中状态和人数；选择成员后旧规划预览失效，智能规划只收到当前所选团队。当前外部 SDK/app-server 支持手动自由协作、流水线及内置主管委派，外部只读 CLI 仅支持流水线；外部成员尚未接入 Coordination 智能规划。组合不兼容时页面保留用户选择、说明原因并提供显式切换模式或仅保留模型 API 成员的入口，阻止启动该组合。
