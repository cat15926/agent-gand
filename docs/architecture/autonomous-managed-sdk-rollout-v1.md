# AC6 托管 SDK、自主准入与排空契约

日期：2026-10-18。对应[实施方案](../plans/agent-autonomous-collaboration-implementation-plan.md) AC6。本文件描述生效实现，实际组合验证见[验收记录](../reports/autonomous-collaboration-ac6-acceptance-2026-10-18.md)。用户批准后的业务环境开放范围与迁移证据见[灰度切换记录](../reports/autonomous-collaboration-service-cutover-2026-10-18.md)。

## 新根与执行器

普通 entryVersion2 新根冻结 `rolloutVersion=1`，策略保存本轮 `executionDrivers`。明确开放托管 Claude SDK 时再冻结 `nativeVersion=1`。schema23 追加托管 SDK/灰度契约，schema24 追加独立 `costVersion=1` 费用语义描述，不重写 18–22 的迁移描述或历史策略。老根不能补字段；旧 worker 在读取新库前拒绝。

本次仅支持 `builtin-llm` 和受控托管 API Key `claude-sdk`。Codex app-server、原生登录、只读 CLI 均不进入自主根。原生 Codex 既有手动与历史协议保持，真实 Codex 验证按用户要求暂缓。

SDK 主 Agent 与成员实现使用同一个 `executeAutonomousDispatch`、Grant、Subject/Attempt、动作命令和根账本，负责人需独立准入。当前真实验收通过鸡腿 SDK 负责人委派 API 成员并汇总交付、API 主持加五名 SDK 玩家的完整游戏，以及 SDK 文件修改加 API 独立复核。准入仍默认关闭，开放时应限定已验证的账户、模型及任务范围，不能从成员能力推断其他负责人组合可用。SDK 是候选传输适配器：

1. 用服务端绑定的 Scope/Attempt 构造一次冷环境，原生工具、记忆、插件、工程规则与会话复用关闭。
2. 只通过 MCP 暴露当前合法的 v4 控制工具及 Grant 允许的受控文件工具，不提供 Owner 管理凭据。
3. 原生回合可以通过受控文件桥产生真实效果；控制调用只捕获一个候选。传输的 v2 complete 标记仅用于结束原生回合，不写为责任完成事实。
4. 等原生进程、桥业务调用和用量收敛，删除冷目录后，再由原执行器验证并提交实际 v4 委派、汇总、公告、问题、流程行动或完成。
5. 同一责任连续 emit/complete 或遇到补充时，每次启动使用不同的服务端派生 launch ID 和冷目录，实际 Scope/Attempt 权威保持，不能把旧候选当成新一轮结果。

AC6 冷回合使用平台完整任务提示词，不附加 Claude Code 通用仓库工作流；通过 SDK 请求低推理强度，并把冻结的每次输出预算传入客户端。实际供应商是否遵循该请求仍以返回用量为准，不将客户端参数视为平台硬限额。角色原始指令、模型、账户及授权范围保持冻结。文件委派明确选择输入句柄与工具；附件目录仅为当前有权读取的文件标示路径和版本，AC6 的上下文与 fs.read 回执同时标明实际快照的路径、版本、产物 ID 与内容 SHA-256，依赖关系不会自动传递新的文件版本，复核产物应通过 aggregate 选择实际结果。流程推进工具只包含当前流程 ID 和当前 step，省去起始字段并明确 expectedStep 不是下一阶段编号，服务端仍验证所有字段。成员参数使用精确 ID，自汇总的 `agentId` 明确为当前成员 ID；aggregate schema 枚举本责任内可选成员，不接受 `self` 等别名，也不自动修补被拒绝的权限请求。

SDK 内部调用数量与硬输出上限无法由平台逐次强制保证。平台预留根剩余输出额度并串行争用，实际报告用量后结算；费用仍按估算策略治理。调用、输出用量或原生效果不确定时保留占额并阻断。仅费用未知且根明确冻结 costVersion1、估算模式和 unknownAction=reserve 时，保留未知费用占额后允许继续与交付；stop 策略及旧根仍阻断，任何路径都不能清空费用或伪称零收费。运行截止及首响应/空闲时限继承根策略；原生候选不能绕过 10 分钟回复配置或根截止。

AC6 原生回合先等待根 token/费用准入，再建立原生执行及其回复计时；队列等待仍受根截止、撤销和停止约束。排队中的模型调用可观测，未准入时不启动原生进程，也不消耗账户的回复窗口。排队暂停会将未发出调用记为 admission_blocked，释放尚未发出的占额，保留同一责任恢复；已发出的未知调用仍不退款或重放。旧根计时语义不升级。

## 真实模型格式适配

AC6 根的模型 API 参数错误在尚未提交动作时最多纠正两次，所有调用记账。无效 JSON、多/无工具候选和无效 complete 参数只得到当前工具格式反馈，不替模型生成业务决定。连续三次无效则失败。权限、来源、代际、未知用量与已经产生的效果不属于格式重试范围。

叶子责任使用对应指令，不要求它执行转交材料中属于上级的分工请求或汇总不存在的子结果；未有已完成子结果时不暴露 aggregate。工作 key、输入句柄与状态回执不是文件路径，文件桥不能读取子结果；需要正文时通过 aggregate 创建有权的新内容责任。旧 AC1–AC5 根的纠正语义不升级。候选进入原 Scope 权限保护的执行审计，公开公告仍只使用获准内容或固定协议转换。已收敛的控制工具若因结束原生回合缺少原生工具结束事件，审计明确标注控制中断，不假报业务工具失败。

## 房间灰度与关闭准入

| 配置 | 含义 |
|---|---|
| `AUTONOMOUS_COLLABORATION_MODE=closed/preview/execute` | 新普通自主任务准入；默认 closed |
| `AUTONOMOUS_ROOM_IDS=*` | execute 下全部房间可准入；默认值；`id1,id2` 仅允许确切既有房间，空值全部关闭 |
| `AUTONOMOUS_NATIVE_DRIVERS=claude-sdk` | 明确允许托管 SDK 新根；默认空值；同时受 scoped 和 orchestration 后端准入约束 |
| `AUTONOMOUS_NATIVE_COORDINATOR_DRIVERS=claude-sdk` | SDK 负责人独立准入，默认空；按确切账户、模型和任务范围验收后显式开放 |

房间限制由 HTTP 服务端校验，前端不能通过改成员或新建房间绕过。重复同键提交仍可查回原根。前端区分参与成员和负责人后端，SDK 成员开放时不会自动出现在负责人选择中；显式提及未开放负责人同样被拒绝。实验准入的 SDK 负责人是普通 execute 角色，不赋予内置 Supervisor/Planner 的 coordinate 权限。

AC6 已启动结构化流程后，负责人当前 Scope 不提供文件工具，只暴露 `agent.flow` 推进；终局仅提供 `agent.complete`，不能再用普通 delegate 建立缺少身份和行动通道的影子玩家。API 隐藏工具候选也在产生效果前拒绝，不能仅靠前端/工具描述隐藏。玩家仍只有 flow_action，原有有界格式纠正保持。

AC6 的关闭准入、移出房间或移除后端只阻止新根。已冻结根继续使用原权限和后端排空，队列领取、恢复、依赖唤醒和终局一致；新配置不能悄悄增加旧根后端。用户 Stop、Grant/账户撤销、预算、来源漂移及期限仍立即生效。页面刷新后仍可补充并恢复进行中的原任务，不误落回旧输入重新开任务。

旧 AC1–AC5 根仍需兼容 worker 和原 execute 条件，不能用新字段改写其关闭含义；运维清单单列此类活动根。

## 维护与回退

`pnpm autonomous:inventory [数据库路径]` 只读检查当前/期望 Schema、是否需要迁移、活动根、执行者/原生进程、队列、决策、未知 token/费用和回退条件。自主根统计之外，`database` 单列全库活动任务、原生/工具未知效果及未知用量；整库回退就绪必须同时满足这些条件，不能因自主根为0而忽略旧手动任务。该脚本不导入应用数据库初始化模块，不加载账户凭据，不调用模型。它也可读取尚未迁移的业务库。

切换前保存匹配版本的 SQLite 一致性备份及受保护账户密钥目录，记录应用 revision 和配置。先在复制库执行迁移、兼容检查及恢复演练；业务库切换须使用 schema24 兼容 worker。实现本身不自动重启或开放日常服务；本地业务环境已在用户后续批准后完成指定房间灰度切换。

关闭新准入后先排空活动根；存在未知费用/效果时保留原账本和兼容 worker，按真实证据处理。需要回退时恢复匹配应用版本与切换前一致性备份；禁止删迁移行/新表或清空 unknown 来假装降级成功。专项在隔离 v22 备份和升级副本中验证旧 worker 拒绝新库、接受原备份；它不代表已经替用户恢复日常业务库。

## 验收工具

- `verify:autonomous-ac6`：真实安装 SDK 连接本地 SSE，覆盖全部 v4 工具、SDK 主持/玩家隔离、问题和私密授权门禁、受控文件/暂停、撤销/停止/来源失效、房间及关闭排空、迁移与备份。
- `verify:autonomous-ac6-ui`：房间内选 SDK 负责人、Codex 排除、关闭准入刷新后原任务补充/恢复、单次交付、手机宽度。
- `autonomous:acceptance-real --sdk-agent <现有角色> --api-agent <现有角色> --case mixed|api|game|files [--execute]`：默认只打印范围，execute 才发送真实请求；冻结原模型、账户、角色指令及权限后走普通 HTTP，不替换 Run 内快照、不预填计划、不模拟模型。

真实验收使用隔离库及私有凭据副本，保存调用、用量、费用和业务库不变证据；失败与未知请求保留，不以后续成功覆盖。SDK 内部供应商请求数如不可观测则标 unknown。每个开放组合都应有对应实际账户、协议、模型和任务范围的证据，不把账户连接或本地夹具通过扩大成全部模型可用。

真实脚本运行生产相同的租约续期与持久等待恢复循环。完成判定要求唯一最终交付、运行时审计通过、模型调用均已结束且输出用量已知；游戏重算全部状态转换，核对每次行动来自真实 SDK、私密材料仅由对应玩家读取；文件场景经普通附件入口，核对 SDK 的实际读取/写入、原版本保留及 API 复核实际新版本。未知费用继续单独保留。
