# 自主任务默认入口 v1（AC4）

状态：2026-10-18，模型 API 适用实现，schema21。关联[实施计划](../plans/agent-autonomous-collaboration-implementation-plan.md)、[AC3 交付契约](./autonomous-result-delivery-v1.md)、[AC4 验收](../reports/autonomous-collaboration-ac4-acceptance-2026-10-18.md)。

## 开放条件与兼容

普通页面在服务声明可用时使用简洁的需求输入区，发送 `entryVersion:2`。服务端要求 `AUTONOMOUS_COLLABORATION_MODE=execute`、统一入口 execute 且启用 builtin-llm 驱动。默认配置仍 closed；未重启日常服务、迁移业务库或自动打开真实模型调用。灰度关闭时阻断新准入，已提交请求的同键查询仍返回原任务，历史查看及停止保留。

新请求复用普通 `POST /api/conversations`、`POST /api/conversations/:id/requests`，消息/直接 Run 兼容路由也识别显式版本。版本 1 与旧请求维持原入口，不自动升级旧 Run；新旧契约不能复用同一提交标识重复执行。进入高级手动编排是明确的用户操作，保留原材料/发布表单与人工阶段契约，不自动回退到原生执行。

`/api/orchestration/options` 返回公开的可用性、驱动与预算上限，不需要把账户管理会话交给 Agent。负责人默认取明确提及、房间可用默认负责人或模型 API 协调/执行成员；可参与成员来自本房间已启用且获准的模型 API 角色。显式 SDK/Codex 对象、不可用账户、房间外成员和不支持的费用策略在 I/O 前拒绝，界面说明对应边界。

## 一次普通发送

输入为目标、可选负责人和参与范围、可见范围、附件、约束及明确引用。页面不要求选择引擎、批次或预填计划。可见设置本身就是这次任务授权；合法普通提交不加通用预览确认页。

一个 SQLite 事务完成校验、Run、根消息、附件版本、冻结策略/角色账户快照、根工作/派发与幂等事实。事务结束后才唤醒现有 Collaboration 调度器，不调用旧房间历史/快速回复入口，不在事务中调用模型。主体、工具、费用及 Token/时限冻结在根上，readonly 实际移除写工具。

本阶段仅使用平台受控文件，不读写本地代码仓库或原生磁盘。附件和明确引用是根内容 Scope 的实际输入；没有自动读取房间历史。普通入口直接处理 UTF-8 文本，目标与材料合计最多 12000 字符，为角色/指令及状态保留原 24000 字符 Scope 上限内的空间；更大或二进制材料在准入时拒绝，不宣称已实现 PDF/图片解析。私密引用必须保留原消息范围，仅复制明确选中的版本；后续原来源版本/ACL 变化仍会阻断使用。

新根冻结 `features.autonomousCollaboration.entryVersion=1`，同时要求 delegationVersion=1、deliveryVersion=1。该字段缺失的 AC1–AC3 根保留原语义，不能通过改开关升级。不是为旧任务改写 Scope 或补充新执行权。

## 同任务补充

`POST /api/runs/:runId/instructions` 接受 `text`、`clientRequestId`、`expectedRevision`，不接受预算、成员、工具、发布范围等字段。登记不可变递增版本与精确消息来源，不另建 Run、不重置账本、不修改已完成工作。补充采用根任务原可见范围。

只有一个活动任务时输入区默认补充它；多项活动任务时必须选择对象或明确新建独立任务。用户也可以主动另开任务。问题/确切授权正在等待时，使用对应卡处理，补充不能代替批准或回答。

未来的根/子调用读入已登记补充并记入实际来源账本。模型 I/O 期间若收到新版本，旧工具动作不提交，已知调用消耗仍结算；再次读入补充后决定后续工作。已完成分支不自动重做；如需重做，由 Agent 在原预算中追加新工作并说明原因。未发布的 final 候选若早于当前指令版本，不能当作最新交付，改用新接受的结果；已经发布的 update 不改写。

提交响应丢失时保留原请求与标识，页面提示重试原提交，不把原目标误当作补充。新任务/补充都有重复与版本冲突检查。私密输入与附件不新增浏览器持久存储；高级入口切换保留当前 React 草稿，恢复需求输入时可继续编辑。

## 暂停、恢复与停止

暂停停止新派发；已发出调用按已有能力收敛并保留用量。在模型或工具效果之间，通过原动作命令创建持久暂停点：同一工作、Subject、Scope、原 Attempt/Dispatch、等待代际及输入回执均保留。暂停不伪装成完成候选或业务问题。

恢复检查原任务已收敛、无 unknown 与待核对副作用，清除暂停标记后唯一创建同 Subject 的 resume。实际已读来源、用户补充和工具回执进入新冷 Scope，已完成写入不自动重放，所有消耗继续记在同一根。新进程同样可恢复；等待子工作或业务问题时保留原义务与决策，不冒充用户回答。

停止复用唯一终局与执行权门禁，关闭等待/排队/未派发工作，迟到模型结果不能发布，已产生消耗与副作用记录不删除。

## 页面进度与高级入口

任务卡取实际 Subject/Custody、Dispatch/Attempt、依赖与 accepted 结果，显示负责人、正在处理/已排队/完成情况、补充版本及根输出已用和占额。默认过程折叠，用户展开后可核对目标、依赖和获准结果；内部贡献消息默认收起，最终交付正常显示。系统交付状态不声称用户已验收业务质量。

高级手动编排中继续保留固定流程、独立材料和确切发布操作；它不是自主普通任务的必经步骤。旧业务门禁和旧任务查看不改变。

## 存储与部署

迁移21追加 `autonomous_submissions`、`autonomous_user_instructions`、`autonomous_pause_points` 三张禁止更新/删除的事实表。执行状态继续来自原权威表，没有另一套调度器。实际 v20 worker 拒绝 schema21；部署应先备份、排空旧 worker，按匹配源码启动或恢复配套备份，不删除迁移号降级。

原生自主工具、自由秘密披露与完整游戏协议仍未开放，真实模型/托管 SDK 组合与上线灰度属于 AC5/AC6；Codex 真实验证继续暂缓。
