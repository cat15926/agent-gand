# 声明产物与独立工作树快照 v1

状态：已完成。2026-10-11，R3 生效契约。继承 [R2 文件权限](./private-interaction-artifact-acl-v1.md)，新增编排迁移 v7。私密/写入自动续跑及副作用核对仍由 R4 实施。

## 归档范围

快照以明确选择的阶段、其冻结交付清单和额外声明路径为范围。每个声明交付都有是否存在及内容哈希；选择的阶段缺少任一必要文件或实质文本时，预览显示不完整，不能确认保存。未选择的阶段列入遗漏，不把部分归档表述为整轮目标达成。

清单包含来源 Run、阶段/交付项、实际验收决定版本、权限与获准成员、文件版本、SHA256、大小、类型、原文件权限和恢复权限。R2 的创建时账本版本不等于业务验收；本快照只在找到对应接受决定或原归档证明时标注验收版本。

声明文本保存完整字节，不使用证据面板的截断摘要替代正文。物理文件保存声明的新增、修改、删除及二进制内容。删除必须由 Git 基线证明。受控文件保存完整不可变版本与认证元数据，原权限继续冻结。所有字节以及 Git 包采用现有主密钥加密，以完整清单绑定 AEAD；清单及载荷各有 SHA256。备份需保留 SQLite 与原主密钥，存在归档时不能创建替代主密钥来掩盖缺失。

阶段接受决定与对应快照在同一数据库事务中保存。归档失败则接受决定回滚，不进入下一阶段。已验收物理文件原目录消失时，可从可信归档取得已确认版本；原文件仍存在但哈希改变、链接替换或类型异常时明确拒绝，不能静默回落到旧字节。

## Git 与受控变更

公开 Run 在绑定目录本身为有提交的 Git 根目录时，归档精确的 HEAD commit、tree 及其树对象闭包；不保存父提交历史、远程地址、仓库配置、hooks 或原生账户目录。恢复创建独立 Git 仓库，将原 commit 设为浅边界并重建索引，因此删除旧工作树和旧 Git 对象目录后仍可恢复原提交。

基线之外仅复制明确声明的路径改动；未声明的已跟踪改动在预览中说明，并在恢复时使用基线版本。未声明的新文件、敏感路径和依赖目录不进入包。不能完整、安全归档的 Git 基线（例如跟踪了凭据、平台数据库、链接或子模块）拒绝保存，不能悄悄改成不完整 Git 基线。非 Git 根目录保留普通文件快照，并说明没有 Git 基线。

支持普通单链接文件；拒绝符号链接、硬链接、特殊文件、子模块、路径逃逸及大小超限。读取使用 no-follow 描述符、父目录、inode、权限和时间校验；预览确认重新编译，变化触发过期预览。排除 `.git`、`.claude`、`.codex`、`.agents`、账户私有目录、平台数据库/WAL/SHM、原生登录文件、`.env`、私钥类文件及依赖目录；允许 `.env.example` / `.env.sample`。这是明确路径策略，不声称能识别任意命名的业务秘密，未声明新文件始终排除。

限制：物理文件/文本单项最多 1 MiB；受控文件沿用 256 KiB；Git 原始文件总量及包读取最多 16 MiB；完整 JSON 载荷（含 Base64）最多 16 MiB；归档及扫描最多 4000 文件/目录条目，额外声明最多 128 路径。限制与遗漏显示在预览中，超限拒绝保存。恢复物理文件为 0600，原有可执行文件为 0700；源权限变化也参与预览指纹。

## 隔离恢复与权限

Owner 先预览再确认，目标仅为平台生成的 `sandbox/restored-artifacts/<clientRequestId>`，阶段续跑为新的 `sandbox/runs/<runId>`。不接受任意目标路径，不写原注册仓库、Git 工作树登记或用户当前 checkout。先在新临时目录验证和重建，再移入目标；已有非空目标不能覆盖。

确认核对快照版本、摘要、全部归档字节、Git 基线、受控文件当前认证元数据与冻结 ACL。归档损坏、缺失的受控版本、权限漂移或不安全路径阻断。重复恢复核对已恢复目录的 commit、哈希、删除记录、链接和权限，不补回漂移或丢失文件；应由所有者核实后选择另一新目录，不能默认修复并继续。恢复中断后留下的未知目录也不会被自动覆盖。

私密受控字节保持加密，仅通过 Owner 下载或已有 ACL 文件工具使用；独立恢复目录不落盘受控字节，无论文件是公开还是私密。私密 Run 不归档物理工作区或 Git 基线。R3 的 Owner 产物恢复不调模型、不重放工具，不等同于私密/写入 Agent 续跑。

## 检查点与保留

新阶段检查点使用 v2，保留 v1 历史读取。v2 行只保存归档标识、摘要与清单，不重复保存明文文件载荷。确认新 Run、归档引用、受控版本迁移、唯一后继及预算结转保持同一事务。

公开只读 `stage_gated` 续跑/返工带入已验收声明及用户输入附件；未验收/被拒绝的受控产物明确遗漏，不能变成后续输入或完成证明。受控文件在新 Run 创建同权限不可变版本，并以 `restoredFrom` 记录原版本与快照来源；旧版本及原验收证据不改写。成员必须具备受控文件读取能力。原生工作目录只恢复物理声明与 Git 基线。

私密/写入续跑继续使用已有拒绝代码，留给 R4。自由协作受控文件的跨引擎承接仍明确拒绝，留给 R6；可先保存 Owner 产物快照。

`artifact_snapshot_refs` 保留验收和检查点引用，`artifact_snapshot_restores` 保留恢复绑定。已验收、被后继引用或已恢复快照不能清理；原受控版本继续按 R2 不可变规则保存。未被引用且未恢复的手动归档可由 Owner 携带摘要明确清理。没有自动过期删除；软删除 Run、归档聊天室或移除旧临时目录不会删除证据。

## 管理接口与页面

以下接口全部沿用账户 Owner Cookie、Host/Origin、远程管理认证、CSRF、no-store；不允许 Agent/viewer 覆盖。清单包含私密元数据，只有 Owner 路由提供。

| 接口 | 用途 |
|---|---|
| `GET /api/accounts/artifact-snapshots/runs/:runId` | 清单、版本与保留状态 |
| `POST .../runs/:runId/preview` | 声明阶段/路径，无模型、无数据库或文件写入 |
| `POST .../runs/:runId` | 重新编译并核对 fingerprint，保存归档 |
| `POST .../:id/restore-preview` | 校验归档及权限，返回恢复范围 |
| `POST .../:id/restores` | 携带 fingerprint 和 clientRequestId，恢复到新目录 |
| `GET .../:id/content/:kind/:index` | Owner 下载完整文本或文件；删除记录无正文 |
| `DELETE .../:id` | 携带 digest，清理未保留归档 |

任务卡展开“查看计划、结果与验收”后，“产物与工作树快照”可声明阶段和额外路径、查看版本/改动/权限、下载、预览和确认新目录恢复。阶段续跑与返工预览复用同一清单组件，说明 Git 基线、保留产物及遗漏。桌面和 390px 页面均有回归证据。

验证与未覆盖事项见 [R3 验收报告](../reports/platform-collaboration-r3-acceptance-2026-10-11.md)。真实供应商、多分支承接、私密/写入续跑和费用治理分别留给 R8、R6、R4、R5。
