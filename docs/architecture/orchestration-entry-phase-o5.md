# 编排入口收敛 O5：每轮任务交互

日期：2026-10-06。

## 页面入口

`TaskComposer` 同时用于创建房间、房间首轮和后续任务。房间保存候选团队、稳定工作区与默认偏好；候选成员不等于本轮执行对象。每条任务独立提交策略、工作流、明确对象、引用和约束。

- 策略：自动、并行分析、顺序接力。接力对象按选择顺序执行，可上移调整。
- 工作流：常规协作、分析与汇总、开发与评审、主管拆解、固定轮次辩论。
- 只读 CLI 明确选择后，需要用户选择顺序接力与只读；页面不自动切换策略。不兼容工作流选项禁用并说明原因。
- Claude SDK 可作为自动策略的候选或明确对象。选择成员、编辑目标、切换控件不会请求规划模型。
- 普通只读任务可以发送时经过规则预览直接提交；复杂工作流和写入任务必须确认预览。主管的规则预览只提示需要详细计划；只有点击“生成详细计划（可能消耗额度）”才调用规划模型。

预览展示真实执行对象、策略、工作流、读写政策、工作区、硬输出预算、执行时限、成员能力/账户配置和阻断原因。主管图展示具体任务、内容、验收标准和依赖。计划出现时滚动到标题并转移键盘焦点。编辑目标、对象、角色、策略、工作流、约束、工作区或引用后，预览失效；提交事务仍校验服务端角色、账户与工作区版本。

`@` 支持精确角色 ID 和名称，包括含空格的名称；优先最长完整名称并保留提及顺序。同名歧义、未知名称或正文与点选对象不一致时返回阻断原因。引用普通消息仍创建新任务；回答原来的 Agent 问题使用原 Decision 入口，继续原任务。

## 房间与默认偏好

新增接口：

| 接口 | 行为 |
|---|---|
| `POST /api/conversations/empty` | 保存名称、候选团队、工作区和默认偏好；不创建 Run、派发、执行占位或模型请求 |
| `PATCH /api/conversations/:id/preferences` | 显式保存默认偏好；使用 `expectedMembersVersion` 防止覆盖其他编辑 |
| `GET /api/conversations/:id/task-state` | 返回各任务冻结快照、暂停/未知状态、队列、最新修订目标和修订限制 |
| `GET /api/orchestration/members` | 返回持久成员占位，用于忙碌和排队显示 |

新建并发送继续使用 O4 的事务入口，支持可选 `roomTitle` 和 `roomPreferences`；这两项也纳入提交幂等摘要。房间默认偏好不参与已有任务执行，不改写冻结快照。选择“将当前选择同时设为新房间默认”或“将当前选择设为房间默认”才保存偏好。发送完成后，下一轮恢复房间默认，并清空本轮对象。

`conversations.preferences` 是可空 JSON 的增量列；旧 `mode` 保留，尚未进行 O6 的全库旧模式偏好回填。旧房间没有明确偏好时，新页面默认显示自动/常规协作；旧 API 和历史任务继续保持兼容语义。自动工作区生成稳定的房间名称，在首次实际执行时创建目录。空房间重启后不会被旧回填流程误归档。

现有房间工作区在输入框中显示；变更工作区通过新房间承载，已有任务继续使用其冻结工作区。

## 任务卡与操作

每个 Run 有独立任务卡，显示实际策略/工作流、目标和状态。取消、暂停、恢复均调用公共 `/api/runs/:id/actions`，作用于指定 Run。成员排队显示前方执行数，取消排队任务不取消其他任务。

尚未准入、没有步骤 Attempt 的步骤图可以立即安全暂停，保存原上下文和检查点，不先调用模型。正在执行的任务等待安全边界。未知原生结果或恢复 attention 会禁用恢复/修订并说明原因。

安全暂停的 O4 步骤图可选择“补充当前任务／修订计划”，沿用冻结的角色、预算、工作流、读写政策和工作区。新目标先预览，再提交 `orchestration/revisions`；确认后仍暂停，用户另行恢复。最新修订目标与原目标同时可查。已开始的写入任务不能重建图，页面禁用修订并提示创建新任务。

审批复用现有 `ApprovalCard`，按原 Run 显示，移动端也可操作；过期或权限错误在卡内显示。展开任务详情可查看当前计划、尝试次数、成功输出和失败原因，活跃任务每两秒更新。失败 O4 步骤图只提供查看部分结果和创建新任务，不提供未实现的分支重试。旧主管正式任务保留既有重试入口，适配器内部步骤不显示重试按钮。完成写任务不代表提交、推送、合并或部署。

右侧面板保留证据和观测，暂停/修订入口收敛到聊天任务卡。任务图与观测均按 Run 选择，并读取冻结配置；历史任务明确标为历史模式，不根据房间 mode 猜测当前执行方式。

## 草稿与布局

建房草稿升级为 `gand:room-draft:v2`，保留目标、团队、对象、工作区和旧显式模式偏好：pipeline→serial/routine，supervisor→auto/supervisor_decomposition，collaboration/auto→auto/routine。迁移显示提示。损坏字段尽量恢复可识别输入，原始内容保留在 recovery 存储，可在页面查看；不直接丢弃整个目标。房间任务草稿按房间保存；仅建房时，已输入的首轮目标也保留。

主输入框固定最大宽度，滚动容器预留滚动条空间。控件在窄屏换行，右侧证据面板仅在宽屏出现，审批仍在任务卡中。聊天侧栏在窄屏自动收起；任务图与观测在窄屏纵向排列。390、768、1440 像素下验证无横向溢出。

本阶段使用本地 mock 和隔离数据库验证交互，不证明真实供应商连接成功。旧模式全量迁移、灰度与回滚属于 O6；真实账户与供应商验收属于 O7。
