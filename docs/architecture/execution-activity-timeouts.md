# 模型活动时限与失败诊断

对应 [Issue #14](https://github.com/cat15926/agent-gand/issues/14)。任务级限制增加可选的 `firstResponseTimeoutMs` 和 `idleTimeoutMs`，随统一入口的预览、指纹、确认请求和 Run 快照冻结。旧任务和留空设置不启用新时限，仍服从原账户/服务总时限、运行截止时间及步骤租约。

## 用户操作

在“执行设置 → 本轮约束与房间默认偏好”填写“模型首响应时限”和“模型停滞时限”，单位为秒。预览显示本次限制。修改限制后必须重新预览；现有任务及暂停图修订不能更换冻结约束。设置可保存为房间默认，浏览器草稿会保留。

任务执行详情分别显示总时限及来源、首响应/停滞时限、失败阶段、账户/工作区/客户端准备环节及原始错误。失败任务卡优先展示真实失败执行的错误，避免后续取消成员覆盖它。证据采集的后续异常单独记录，不替换执行原始失败。

## 时钟语义

| 时限 | 开始与重置 | 不计入的等待 |
|---|---|---|
| 首响应 | 每次 API 模型请求或原生 `driver.invoke` 开始；首次正文、思考增量或工具请求活动停止计时 | 成员排队、工作区准备、原生版本检测、平台会话准备 |
| 停滞 | 首次模型活动后开始；每次新正文、思考增量或工具请求活动重置 | 平台工具执行与审批发生在 API 请求之间；原生工具/原生审批期间暂停，全部等待结束后重新计时 |
| 总时限 | 沿用账户/服务设置；冻结 Run 截止时间和步骤租约优先取最早期限 | 不因工具或审批等待而延长 |

只设置停滞时限时，不额外限制第一次响应前的等待。原生客户端启动与供应商认证发生在 `driver.invoke` 内，因此计入首响应等待；会话绑定和用量事件不能假装模型已响应。原生回合纠偏和已确认不可用的会话冷启动各自重新开始首响应时钟，总时限不重置。

`response.activity` 仅传活动类型，不携带思考文本。OpenAI 兼容流和 Anthropic 流保留原正文/工具分片解析，同时传思考与工具请求活动元数据。Claude SDK/CLI 解析器与 Codex 后端映射已识别的思考事件。未知协议事件不充当保活信号；没有思考增量的供应商仍可能在首响应时限内超时，需按模型实际延迟设置。

首响应和停滞使用独立计时器，超时通过同一个执行 AbortSignal 停止原生进程。API 调用增加取消竞争和回调围栏：即使供应商实现不响应取消，也不会无限等待或把晚到正文继续广播。未确认的调用消耗继续保留原 Token 预约，禁止自动重发；平台取消不保证供应商免于计费。

## 数据与失败边界

约束接受 1～86,400,000 的整数毫秒，未知字段、0、负数和非整数拒绝。HTTP 不增加协作模式或第二条调度队列。

外部执行保存 `timeoutPolicy.firstResponseTimeoutMs/idleTimeoutMs` 和 `progress.firstResponseAt/lastActivityAt`。错误细节保存 `timeoutKind`（`total/first_response/idle`）、`limitMs`、`phase`，执行准备错误另存 `initializationStep`（`workspace/account/client`）。内置 API 的 LLM Span 同样保存失败阶段和时限类型，主管分析/汇总也使用公共预算与时限入口。

工作区解析、账户解析以及准入前准备失败会形成持久执行记录，即使未启动进程。完成/失败的作用域不会被覆盖或自动重放。被成员准入拒绝的并发重复调用不能写入失败记录污染仍在准备中的有效调用。记录的未知 Token/费用沿用现有显示，不能当作 0。

证据采集异常写入 `failureDetails.secondary`。R1 已增加[Run 失败关系诊断 v1](./run-failure-diagnostics-v1.md)，通过持久身份、前置依赖、关闭前快照和实际取消原因区分多分支失败；API Span 补触发时限与可信活动时间，HTTP 错误补已观测 Request ID。原生 SDK/Codex 联合夹具和真实本地 HTTP/WS/浏览器回归见[R1 验收记录](../reports/platform-collaboration-r1-acceptance-2026-10-11.md)；真实供应商长链路仍待 R8 验证。

## 验证

- `pnpm verify:execution-diagnostics`：受控时钟检查独立时限、嵌套工具/审批暂停、默认关闭、重复调用时钟、取消竞争；stdio 夹具检查脱敏诊断和进程清理。
- `pnpm verify:execution-timeouts`：临时数据库、冻结入口、配置漂移、草稿/房间偏好、内存 HTTP 供应商流、未知预算围栏、API 晚到输出、原生 CLI 超时/慢工具/思考活动、初始化失败持久化、排队隔离及任务主错误选择。
- `pnpm verify:external-agents`：现有 CLI 协议、只读策略、错误、用量、并发、取消/总超时及完成结果复用；预览阻断与活跃重复调用断言同步现有规则。

这些检查不监听端口、不使用真实凭证、不请求真实模型。
