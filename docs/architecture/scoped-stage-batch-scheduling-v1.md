# 差异化阶段批量调度 v1

状态：2026-10-12 生效，对应剩余实施计划 R7。验收见[R7 记录](../reports/platform-collaboration-r7-acceptance-2026-10-12.md)。使用业务契约 schema v3、原有 Coordination 冻结图与追加迁移 v11；不新增顶层协作模式。历史 v1/v2 契约及 R6 修订号保持原含义。

## 1. 交互与范围

在“执行设置 → 逐阶段执行”中启用“差异化批量任务”，分别编辑成员目标、依赖和信息范围，设置并发上限，按需安排独立成员汇合。预览显示预计最少回合、就绪批次、接收人、可见范围、明确的汇合输入和验收条件。确认后执行，交付面板仍由 Owner 登记证据并逐项验收。

依赖空数组表示独立，缺失表示原顺序链。升级草稿会显式保留原有顺序依赖，不把旧工作自动变成独立任务。关闭批量设置会清除逐成员范围和汇合，恢复本轮统一范围，须重新预览。草稿阅读器保留 v3 字段，损坏或未知结构不自动当作可信执行契约。

共同目标及输入附件继承 Run 范围。成员的独立目标、回复、工具、文件及证据另受各自范围约束。Owner 可以审计全部数据；“接收人”用于执行，“谁能看到”用于数据授权，两者分别展示。

## 2. 契约 schema v3

v3 必须使用 `stage_gated` 且包含正整数 `revision`。v1/v2 请求不能携带新字段。

```json
{
  "version": 3,
  "revision": 1,
  "executionMode": "stage_gated",
  "stages": [{
    "id": "analysis",
    "title": "分别分析与汇合",
    "criteria": ["分别提供依据，汇合保留差异"],
    "deliverables": [{"id": "result", "title": "汇合报告", "kind": "text"}],
    "execution": {
      "concurrency": 2,
      "assignments": [
        {"agentId": "aa", "objective": "分析 A 的专属资料", "dependsOn": [], "visibility": "private", "audience": ["aa", "summary"]},
        {"agentId": "bb", "objective": "分析 B 的专属资料", "dependsOn": [], "visibility": "private", "audience": ["bb", "summary"]}
      ],
      "join": {"agentId": "summary", "objective": "对照获准结果并保留差异", "sourceAgentIds": ["aa", "bb"], "visibility": "private", "audience": ["summary"]}
    }
  }]
}
```

并发参数为 1–8，空值使用服务端上限，实际上限取声明与服务端的较小值并冻结到步骤。依赖仍只引用同阶段较早声明的成员，禁止环、重复及外部成员。

逐成员 `public` 或省略范围表示继承 Run；`private` 必须包含执行成员，且不能超出冻结团队或本轮私密授权。Owner 自动保留权限。依赖输入须允许接收成员阅读，并且接收任务的输出范围必须在该来源范围内；不能让读取了窄私密数据的工作发布到更宽范围。

汇合是可选的额外模型回合，成员不得同时承担本阶段普通分工。`sourceAgentIds` 必须非空、不重复且属于本阶段分工。执行等待全部阶段成员完成；上下文只读取显式选择、已确认且授权相容的当前阶段结果。未选择的结果即使可读也不拼接，未授权输入在预览被拒绝，不通过模型摘要自动扩权。不配置汇合时平台收集各份交付，不额外调用模型确认。

阶段、分工、汇合和门禁合计最多 64 个步骤；原有阶段数量、文本大小、时限、Token 和费用规则继续适用。

## 3. 冻结图与执行

每个成员目标直接编译成独立步骤，指定 actor、依赖、范围、工具和一次尝试；汇合编译成有全部成员完成屏障的 aggregate。阶段门禁只在全部必要步骤完成后就绪，Owner 验收之前不会开始下一阶段。普通“恢复”不能跳过验收。

v3 使用可补位的执行窗口：活动步骤数受有效并发上限约束，每次有步骤完成就重新检查就绪项。A 完成时，其下游 C 可在独立慢任务 B 仍执行时启动，无需等待整批 B 结束。汇合仍等待所有必要成员完成。不同阶段的并发上限分别生效，服务端配置变动使尚未确认的预览过期。

写入阶段保持顺序。无依赖并不证明共享写入可并行；显式请求写入并发大于 1 会被拒绝。取消使活动 API 信号及原生执行权失效，后续队列不派发；失败保留已启动的独立结果，停止尚未领取的分支和汇合；暂停停止新领取，活动工作走到安全边界。预算队列中未发出的请求保留可恢复票据与原 Attempt，不记录成已结束模型调用或原生准备失败。

平台 claim 与步骤状态构成持久化派发回执。依赖满足、门禁、暂停和终态沿既有事务、责任及 Completion Engine 更新，不调用模型确认状态。模型仍负责分析、实质结果、评审或用户显式安排的汇合。纯 `ACK/收到` 在 execute/off 均被拒绝为交付，不因有回执或服务端生成 complete 候选就获得验收。

## 4. 上下文、工具与会话隔离

冻结的步骤范围进入 `attemptAccess` 和 Context Assembly；execute/off 都保存对应范围。阶段提示仅包含当前成员获准的分工，依赖正文和证据同时检查 actor 与目标范围，原结果消息及终态报告继承相同授权。

含逐成员私密分工的批次整轮使用受控文件工具：即使某一成员自己的任务为公开，也关闭普通网络、命令及原生文件工具，防止通过旁路读取其他成员的资料。此限制在预览说明。文件读取/检索/写入继续检查当前 Attempt 范围，私密字节保持加密；模型不能通过伪造 ACL 字段公开文件。

v3 的普通工具下发及实际执行均受冻结工具集合约束，Readonly 角色不能通过隐含全局读工具或伪造 tool call 扩大集合。必要附件还校验实际剩余步骤的文件工具，不只看后端抽象能力。

Claude SDK 与 Codex app-server 沿用已有会话绑定，核对账户、角色版本、模型、工作区、权限、Run 信息边界和步骤。成员范围改变不会复用含旧私密数据的会话。原生客户端内部推理请求不能由平台完整测量；平台只报告启动的原生回合。

## 5. 预算、计时与调用账本

输出 Token 与费用继续使用[R5](cost-budget-governance-v1.md)的原子准入：额度被进行中调用占用时，v3 请求进入等待；预约释放后才继续，不能同时消费相同余额。未知用量/费用按原政策保留，不当作零；耗尽或停止政策阻断新派发。旧非 v3 的费用预约冲突行为保留，不悄悄改变历史工作流。

准入等待计入 Run/阶段总时限。模型首响应、停滞和调用执行计时从实际调用开始；预算等待有独立的队列阶段，不报告为供应商无响应。未发出请求的暂停可以恢复，已发出的未知调用不默认重发。SDK 首次费用预约在原生初始化前完成，避免等待被误记成不可重放原生失败；已完成缓存重取不再预约一次费用。

新增 `orchestration_model_calls` 仅记录 Run、Attempt、成员、后端/模型、排队、调用开始、结束和等待原因，不保存提示、结果或凭据。`waiting` 与 `admission_blocked` 不计入已启动请求；API 在调用 provider 前、原生在 invoke 前记开始。提交开始与供应商实际收到请求之间不是原子事务，崩溃窗口保持未知，不能据此证明实际账单。

Owner 的 `/api/accounts/business/:runId/scheduling` 返回 API 请求数、原生启动数、未成功完成/未知结果、准入等待、派发回执、平台门禁及逐步骤状态。沿用 cookie、CSRF/Origin 管理边界和 `no-store`。API 统计覆盖工具/收尾请求，不把仅创建的 LLM Span 当作已发出请求；历史任务标为部分覆盖，不伪报过去实际调用为零。

预览给出最少成员/汇合回合与依赖就绪批次，沿用冻结 Run/阶段预算。工具轮次、服务异常和原生内部请求可能增加规模，此估计不等于供应商报价或严格账单上限。

## 6. 返工、恢复与发布

公开 v3 文本阶段复用[R6](branch-rework-contract-revision-v1.md)部分返工和契约修订，汇合属于所有成员的下游：只重做 B 时也使汇合失效，A 保留；新的汇合继续取得 A 的可信来源结果。标准或汇合配置修改仍使受影响阶段重新交付与验收，原账本不覆盖。费用、Token、唯一后继和原事务规则不变。

逐成员窄私密状态的跨 Run 迁移尚未开放。比 Run 更窄的文本/文件继续明确阻断检查点，不能把各成员全文合成更宽范围或用 Owner 副作用核对绕过授权。相同原 Run 的安全暂停恢复可以保持这些范围；共用 Run 范围的私密/写入阶段仍按[R4](private-write-stage-recovery-v1.md)恢复。R7 不放开任意共享写入、any 竞速、动态嵌套批次或自动发布私密摘要。

追加迁移 v11 `scoped-stage-batch-scheduling-v1`，不重写旧描述和历史任务。仅支持到 v10 的 worker 在写库/执行前拒绝，避免忽略范围、汇合和调用账本。

验证入口为 `pnpm verify:stage-scheduling`，可加 `--kernel-off`；实际本地 SDK/Codex stdio、当前桌面/手机交互、R6 返工、R4/R5 恢复预算及 O6/真实回环 HTTP/WS 分层记录。真实供应商联合长链路仍由 R8 验收。
