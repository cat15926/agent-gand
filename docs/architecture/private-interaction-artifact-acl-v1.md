# 私密交互与受控文件权限 v1

状态：本地生效（2026-10-11），对应剩余计划 R2。[验收记录](../reports/platform-collaboration-r2-acceptance-2026-10-11.md)。

## 用户入口与冻结范围

任务输入提供“公开 / 私密”、获准成员和附件。执行者与获准成员分别选择：公开定向只决定谁执行，私密范围决定谁能看。自动选人仅从获准候选中选择，主管、评审者和汇总者同样需要授权。预览抽屉直接显示“谁能看到”和文件继承范围；私密任务或含附件任务必须预览确认。

`visibility`、`audience` 与附件路径、大小、类型、SHA-256 进入规范化请求和确认指纹。私密范围包含房间所有者 `user`，至少需要一位房间成员。附件每轮最多 4 个，每个最多 256 KiB；文本和二进制均可下载，模型文件工具按文本解码。禁止绝对路径、空段、点段、共享区、归档和执行配置目录。原始 Base64 不进入预览、Run 冻结快照或消息。

私密引用默认继承来源；公开或更宽的引用被拒绝。图修订保持原 Run 的信息范围，不能新增或替换附件；文件变化应创建新任务重新确认。浏览器草稿保存文本和范围，不保存附件字节；损坏的范围恢复为私密空授权并提示重新选择。发送后下一轮恢复公开，私密消息引用则重新继承其范围。

## 编排与后端能力矩阵

| 编排机制 | 模型 API | Claude SDK / Codex app-server | 只读 CLI |
|---|---|---|---|
| Collaboration 开放协作 | 私密文本、平台读/检索；角色允许时私密平台写入 | 私密文本与角色获准的受控文件读/检索/加密写入；关闭原生文件、shell、网络 | 私密任务拒绝 |
| Coordination 步骤图 | 在冻结授权内执行、评审及汇总；平台文件工具按角色权限开放 | 私密步骤、评审及汇总；角色获准的文件读写经平台桥加密处理 | 私密任务拒绝 |
| 兼容 Pipeline / Supervisor 共享上下文 | 统一私密入口拒绝 | 统一私密入口拒绝 | 拒绝 |

旧 Supervisor 共享上下文机制与统一工作流中的 `supervisor_decomposition` 不同；后者编译为 Coordination，仍需规划主管及全部执行成员获准。角色必须声明可用的 `fs.read` 或 `search.files`，才能接收含附件任务。外部原生私密写入当前明确拒绝，内置私密写入仅进入受控产物库。现有账户、工作区、预算和工作流准入仍适用；能力声明不代表供应商连接或模型行为已验证。

不支持的组合在预览中返回具体阻断项。权限错误不会触发静默换引擎、自动公开或自动扩大授权。

## 文件版本与存储

`managed_artifact_versions` 保存不可变版本：房间、来源 Run、任务/Attempt、阶段、创建时验收账本版本、路径、版本、可见范围、授权成员、内容哈希、大小、类型和创建者。附件与 Run 在同一事务内提交，重复确认复用原 Run，不重复创建版本。来源任务或阶段字段不适用时为 null；记录验收版本不等于文件已被业务验收。

文件内容使用现有受保护主密钥进行 AES-256-GCM 加密；完整版本元数据参与 AAD 认证。读取先验证数据库绑定、元数据、内容大小及哈希。私密内容不写入普通原生工作目录，因此知道路径、使用链接或直接调用原生读取，不能取得虚拟私密文件。此加密针对受控文件；消息与 Trace 仍沿用平台存储和访问权限，不宣称端到端加密。

追加数据库迁移 v6：`private-interaction-artifact-acl-v1`。受控文件或 R3 快照已存在时，丢失主密钥不能通过自动创建新密钥“修复”。备份/恢复须同时保留数据库与原受保护主密钥；完整产物保留和归档机制见[R3](./artifact-worktree-snapshots-v1.md)。旧 worker 按迁移兼容门禁拒绝不认识的版本，历史任务不会自动补授权或重分类。

## 读取、证据、汇总与会话

- 平台工具上下文中的 Run、成员及 Attempt 由服务端绑定，不接受模型参数替换。读取既校验成员获准，也校验文件来源范围能够覆盖当前任务的整个范围。成员曾经获准的窄范围文件不能进入其后续公开任务。
- `fs.read`、`search.files` 和受控文件目录使用相同 ACL；已知但未获准的路径拒绝，不能回落到物理文件。文件版本按当前可见的最新版本选择。普通文件路径解析同时限制工作区边界、账户/数据库私有路径、符号链接逃逸和硬链接；托管 Codex 的原生 deny profile 同时拒绝账户目录及数据库、WAL/SHM 的读取。
- 受控 `workspace_file` 证据绑定文件 ID、版本和哈希；缺少绑定、内容变化、房间不符或越权均拒绝。依赖 EvidenceBundle 即使经所有者校验通过，注入步骤上下文时仍按实际成员与当前 Attempt 范围重新解析。
- 新统一私密 Run 的派生消息和上下文继承冻结范围。旧公开 Run 内的私密 Dispatch 仍按各自来源独立解释；私密子任务的工具结果、中间正文及系统提示显式继承 Attempt，历史公开内容保持公开。汇总、交接和引用不能扩大来源权限。
- 原生会话绑定包含私密范围和 Run；即使没有旧版可见性 feature 标志，私密会话也隔离。切回公开会话使用不同绑定。退出纠偏仍只开放控制工具；正常私密回合可以开放角色获准的平台读/检索工具；R4 追加配置 `fs.write` 后的加密受控写入。

## 所有者扩大授权

房间菜单“受控文件与授权”提供版本、范围、来源和下载。管理接口沿用账户管理的 Owner 会话、Host、Origin、远程认证与 CSRF；不接受 Agent 的 viewer 覆盖。

`POST /api/accounts/artifacts/:id/release` 要求最新版本、明确新范围和原因。确认创建新文件版本及 `artifact_authorization_audits`，保留原版本和旧证据权限。仅所有者可以扩大授权；模型没有发布工具。版本变化时拒绝过期确认。

## 保留边界

私密/写入 `stage_gated` Coordination 续跑与整阶段返工已由[R4](./private-write-stage-recovery-v1.md)接入，使用加密检查点 v3、原授权范围与所有者副作用核对。更窄子范围继续由 `PRIVATE_CHECKPOINT_UNSUPPORTED` 阻断。完整受控产物、Git 基线与新隔离目录恢复已由[R3 产物与工作树快照](./artifact-worktree-snapshots-v1.md)交付。公开只读逐阶段检查点 v2 已支持受控文件；[R6](branch-rework-contract-revision-v1.md)现接入适用公开只读图的受控文件承接及明确兼容矩阵。私密/写入通用跨引擎图仍明确拒绝，不能用 Owner 产物恢复替代 Agent 执行契约。

此权限契约约束平台投递、工具和上下文，不限制房间所有者审计，也不替代主机文件权限或可信供应商边界。真实账户、长链路、多阶段混合供应商验证仍由 R8 跟踪。
