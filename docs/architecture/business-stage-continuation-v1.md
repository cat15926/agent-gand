# 阶段续跑检查点 v1

失败的公开只读逐阶段任务，可以由所有者预览并确认建立一个关联 Run。已验收阶段继承原报告、验收决定及证据来源；已完成成员步骤作为确认输入复用，从新执行图移除。新 Run 只执行未完成步骤，并继续经过原阶段验收门禁；不会复活原 Run 或重放已完成调用。

## 交互与支持范围

失败任务卡显示续跑资格及阻断原因。点击“预览阶段续跑”时不调用模型，页面展示剩余事项、继承的已验收阶段、确认输出摘录、归档文件路径与 SHA256，以及时间和输出预算。确认后使用当前角色与账户建立新会话；后续任务卡可查看原任务及继承进度，再按原清单登记并验收剩余阶段。

该入口仅支持 `stage_gated`、Coordination、已失败、公开、只读且进程/工具/调用消耗已收敛的 Run。模型 API、Claude SDK、Codex app-server 均可参与，沿用原冻结阶段分工，并重新验证当前角色和账户配置。不支持已取消、已完成、业务结果已固定的任务，不自动推断被拒绝交付的返工。旧的执行后验收清单没有阶段派发边界，仍须核对后新建任务。

新 Run 使用 `workspace=null` 的独立目录。仅复制已验收、已登记哈希、普通且不超过 32 KiB 的必要文件；原注册目录、仓库基线、未验收产物和失败步骤的部分变更不会带入。预览明确说明此范围，依赖完整原仓库的后续事项应另行配置新任务。本入口不提供写入工作树恢复。完整检查点载荷上限 1 MiB；超限明确阻断，不能静默截断证据。

## 确认与持久化

Owner 路由为 `POST /api/accounts/business/:runId/continuation-preview` 与 `POST /api/accounts/business/:runId/continuations`，沿用管理 Cookie、CSRF、Host、Origin 和本机/远程认证校验。原公共续跑路由不能读取阶段验收归档或绕过 Owner 确认。

预览指纹包含源账本版本、冻结阶段契约、确认输出及文件内容哈希、预算占用、当前配置和新步骤图。确认重新校验；源验收记录、内容或角色账户发生变化时要求重新预览。每个源 Run 只允许一个关联续跑，提交重试复用既有 Run，不同确认载荷返回幂等冲突。完整检查点、新 Run/Plan、关联记录和预算结转在同一事务中提交；准入后的持久化 pending Run 沿现有恢复入口执行。

`business_run_checkpoints` 保存不可变归档，检查点哈希同时冻结到 `RunOrchestrationSnapshot.businessCheckpointDigest`。读取时校验内容与冻结哈希；丢失或损坏时拒绝执行。输出保留原 Run/Attempt/阶段/步骤来源，引用时只允许本检查点明确列出的同阶段输出，不开放任意跨 Run 证据。已验收结论作为继承状态呈现，不伪造新的模型 Attempt、报告或验收事件；新 Run 的追加验收历史仍只包含实际在本轮提交的决定。原账本在关联续跑后封存，仅精确幂等请求可读回旧决定。

已验收文件字节保存在归档内。执行前复制到新 Run；路径包含链接、不安全前缀、越界、同名不同版本，或目标内容已经变化时阻断。重复启动只确认已有文件哈希，不覆盖变化文件。原文件删除后，已提交检查点仍能提供原确认内容；源文件在确认前发生变化则不能迁移旧结论。

追加编排迁移 v4，旧 worker 在写库及恢复前拒绝不支持的数据库，避免忽略检查点后重放已完成步骤。保留原备份和兼容 worker 回退流程，不降级数据库。

## 时间与输出预算

预览明确告知：新 Run 的截止时间和待续阶段时限重新计算，重试可能消耗额度。已占用的硬输出预算以结转预约保留在 Run/阶段预算中，后续预约只使用剩余额度；不能通过新 Run 重新获得原已消耗额度。预算已耗尽而仍有成员任务时，预览直接阻断。

未知调用预约、未收敛进程、未知工具副作用和私密上下文均阻止迁移。结转数字是硬输出预算账本，不代表全部账单、输入 Token 或货币费用。未配置硬输出限制时不创建这类预约，模型用量仍在原执行记录中显示。SDK/app-server 仍不接受无法落实的输出 Token 硬限制。

## 验证

- `pnpm verify:business-stage-continuation`：临时 SQLite 与 API mock，覆盖已验收前缀/阶段内完成步骤不重放、原记录不改写、同阶段证据、预算结转、未知/私密/返工围栏、预览漂移、文件归档迁移、链接/内容漂移、缺失/损坏检查点、Owner HTTP/CSRF/来源与冷进程读取。追加 `--kernel-off` 检查兼容执行路径。
- `pnpm verify:business-stage-gates`：本地 stdio 模拟客户端验证保留已验收 Claude SDK 阶段、Codex 超时后的配置漂移拒绝、新 Run 仅执行 Codex 和后续 API，再验收达成目标；不请求真实供应商。
- `pnpm verify:business-stage-gates-ui`：先构建 Web，沿用可选 `PLAYWRIGHT_MODULE` / `CHROMIUM_EXECUTABLE_PATH`。真实浏览器操作桌面和 390px 续跑预览、Owner 确认、继承展示、后续登记与验收；页面/API/WS 事件来自内存夹具，不监听端口，不代表真实网络或真实模型验收。

被拒绝交付须通过[公开只读阶段返工](./business-stage-rework-v1.md)明确预览和确认。返工中途失败后，本续跑入口保留已冻结修订要求与拒绝归档，继续跳过已完成返工步骤。私密/写入返工、多分支/跨引擎检查点、写入工作树迁移、货币硬预算、文件 ACL 和完整归档仍未实现。
