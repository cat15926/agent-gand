# Run 与阶段费用预算治理 v1

状态：已生效，2026-10-12。对应[剩余计划 R5](../plans/platform-collaboration-remaining-implementation-plan.md)，本地证据见[R5 验收记录](../reports/platform-collaboration-r5-acceptance-2026-10-12.md)。

## 适用范围与限制强度

费用政策绑定统一入口提交的 Run，作用于模型 API 请求及外部 Agent 的每次原生回合。Run 级预算覆盖全部成员，逐阶段任务可以再设阶段费用上限。它与既有输出 Token 硬预算分别记账。

| 后端 | 派发前控制 | 完成后依据 | 严格供应商账单上限 |
|---|---|---|---|
| 模型 API | 有完整手工计价时估算输入和请求输出额度，否则按未知政策处理 | API usage 与冻结价格；缓存和额外收费项必须可解释 | 不支持 |
| Claude SDK | 每次原生回合保留未知额度 | 当前回合可信 USD 费用报告；没有报告则未知 | 不支持 |
| Codex app-server / 只读 CLI | 每次原生回合保留未知额度 | 当前回合可信 USD 费用报告；只有 Token 数不能推出原生内部总费用 | 不支持 |

所有后端能力声明均为 `estimate_only`。`strict` 在预览和实际调用前拒绝，不能静默切成估算。`estimate` 控制平台的新派发，不能保证供应商账单上限：API 输入估算不是 tokenizer，原生回合可能包含多次内部模型调用，已发出的费用不能撤回。实际报告超过预算时如实占额并停止后续调用。

账户测试、规则预览、平台外调用不计入本 Run。付费详细主管规划发生在提交前，当前带费用政策的主管规划明确拒绝；请使用确定性工作流或明确阶段分工。没有政策的历史任务维持原准入行为，不反推历史费用或自动补造供应商账单。

## 冻结政策

`constraints.costPolicy`：

```json
{
  "version": 1,
  "currency": "USD",
  "maxCost": 1,
  "mode": "estimate",
  "unknownAction": "reserve",
  "unknownReserve": 0.1,
  "prices": []
}
```

该示例是 Owner 自定的预留政策，不是模型价格。支持 USD/CNY，不自动换汇。Run 上限及未知预留必须大于零，金额和价格最多六位小数、最大 1,000,000；数据库用币种百万分之一的整数保存，估算和计算费用向上取整。

每个手工价格绑定 `agentId`、**完整且精确的 model**、`source`、`version`，以及输入/输出每百万 Token 单价、可选缓存读取/写入单价。`otherCharges` 为 `none` 时表示 Owner 已核对没有未覆盖收费项，否则为 `unknown`。没有获取“最新模型价格”、币种转换或价格自动替换。更换模型后原价格不匹配；账户/成员配置改变要求重新预览。

阶段 `execution.maxCost` 继承 Run 的币种、计价与未知政策；阶段单独设上限而缺少 Run 政策会拒绝。新任务和明确保存的房间默认可复用政策，但每个新根任务拥有自己的预算；该功能不是跨聊天室账户总额度限制。

## 预约、结算和未知

调用前在 SQLite 事务中汇总已占用额度并写入预约，再执行 I/O；Run 与当前阶段同时校验。并发请求看到彼此的预约，不重复消费同一额度。与输出 Token 预约同事务，费用拒绝时不会遗留一个尚未发出的 Token 调用。

API 输入估算使用消息与工具 schema 的 UTF-8 字节、余量和固定开销，输入单价取适用输入/缓存费率的最大值；输出按请求 `maxTokens` 或配置上限估算。这仍是估算。没有完整价格、其他收费项未知及全部原生回合使用：

- `unknownAction=stop`：调用范围/价格未知时拒绝，调用后用量未知时保留已有预约并停止新派发。
- `unknownAction=reserve`：必须显式设置正数 `unknownReserve`；每次未知调用占用该额度，有余额才允许下一次调用。

结算状态与占额：

| 状态 | 已占用额度 | 后续处理 |
|---|---|---|
| `pending` | 预约额度 | 等待该调用；其他调用仍需通过共同余额检查 |
| `settled` / `carried_known` | 已知费用 | 分开标记后端报告或按版本计价 |
| `unknown` / `carried_unknown` | `max(预约额度, 已知部分)` | 保留未知标记，不能把未知部分结算为零 |

缺失 usage、输入或输出仅部分已知、缓存单价缺失、非法缓存计数及无法识别的非零收费字段，均保留未知。API 已知部分单独计价；真实已报告零用量可以按零结算。OpenAI 缓存从总输入中拆分，Anthropic 普通输入、缓存读取及写入分别计算，流式 usage 合并后再处理。

原生 Token 聚合不用于计算原生总费用。可信的当前回合 USD 报告单独标记为“后端报告”，不当作供应商账单证明，也不能直接结算 CNY。原生纠偏与失效会话的冷重试都是独立回合，分别预约；无二进制、工作区初始化失败等调用前失败不预约原生费用。

发出调用后失败或取消会保留未知，即使已有部分费用报告。调用前已取消不预约。启动恢复将未结算 `pending` 变为 `unknown`，不因服务重启释放额度。报告过量如实记录，`remaining` 显示零并标记超额。

## 续跑与返工

现有只读自由协作续跑和 `stage_gated` 阶段续跑/整阶段返工继承全链路费用。冻结政策的币种、价格及版本不得改变；完成步骤、失败调用和历史未知预约全部结转，重新执行的步骤另产生费用。

来源调用 ID 在每个后继内唯一。多代承接保持原来源 ID，避免重复结转；原记录不被改写为结算。后继、费用导入、检查点及唯一关联均在既有事务中提交，故障整体回滚，响应丢失精确重试复用原后继。费用耗尽和进行中的调用阻断关联恢复，停止政策的未知费用不能借后继绕过。

自由协作的费用续跑使用 Owner 管理入口，预览返回账本摘要及 `costCarryDigest`。确认时重新核对费用摘要；账本变化要求重新预览。阶段费用随检查点摘要一起冻结，包含加密检查点 v3 的私密/写入场景。副作用核对包含费用账本指纹；Owner 核对业务交付不会消除未知费用或释放预约。

适用公开只读跨引擎图、部分成员返工及契约修订已由[R6](branch-rework-contract-revision-v1.md)接入本账本契约；同一来源仍只有一个后继，多分支指图内分支，不能理解为可同时派生多个后继或重置额度。私密/写入通用跨引擎图明确拒绝，逐阶段任务继续按 R4 核对。

## Owner 交互和审计

任务“执行设置”启用费用控制，选择币种、Run 上限、模式和未知政策；展开“成员计价”填写模型的来源、版本和单价，阶段编辑器可另设阶段上限。切换币种清空旧价格并要求重新核对。浏览器草稿保存政策；损坏政策保留原草稿并恢复到禁止派发的严格模式，避免静默去除费用约束。

预览说明限制强度、价格缺口和未知预留，严格模式不能确认执行。任务费用面板显示后端报告、版本计价、进行中预约、未知保留、已占用、余额、阶段上限及继承条数；即使未知余量显示零，未知调用数仍保留。续跑/返工预览展示继承额度。

`GET /api/accounts/business/:runId/cost-budget` 使用既有 Owner Cookie、Host/Origin 约束和 `no-store`。汇总包含全部历史，明细仅返回最近 100 条，包括计价来源/版本和继承来源。该接口只读，不调模型、不提供改写账本入口。

追加迁移 v9 `cost-budget-governance-v1` 创建 `execution_cost_reservations`。旧 span 数值成本仍作为兼容投影保留，但缺价格/usage 或失败调用必须显示未知覆盖；费用面板以新账本为准。只有旧记录且未启用政策的历史任务，不宣称完整账单覆盖。
