# 持续协作：持久调度与根预算合同 v1

T06，2026-10-20。产品名“持续协作”，内部模式 `threaded`。本合同在 T03 执行、T04 资源与 T05 消息之上建立确定性闭环。真实 API/SDK、输入 manifest、游标和 Session 上下文在 T07 接入；文本提及、fallback、等待与征询在 T08 接入。生产新工作入场和真实执行继续关闭。

## 持久身份和原子边界

每个 Wake 对应一条持久队列记录，保留源消息、wave、inputMaxSeq、因果根和原排队序号。一个 Wake 只映射一个 Invocation；不同来源不按正文相同或目标相同合并。Invocation 可先等待，Run 只在首次完整资源领取时创建，重试复用同一 Run/root。

首次领取将预算预留、完整资源 claim、Run/Attempt/Binding 与队列 dispatch 一起提交。预算、控制或权限不合格的记录不占执行容量。资源协调器继续负责跨模式公平竞争与完整资源集合；队列负责 Wake 资格及同槽顺序，不另建一套全局容量或公平性权威。队列年龄保留不等于尚未创建的资源 ticket 已有全局年龄。

响应提交由生命周期拥有最外层 SQLite 事务。预算结算、响应 Message、Delivery/Wake/Outbox、输出证据、Attempt、Invocation、Run 终态及队列投影共同提交。消息附带原来源引用，默认继承来源可见性，仍由 T05 ACL 拒绝扩大私密受众。结构化响应目标用于测试端口；T06 不解释正文 `@`。独立 post 已提交的消息不随之后的最终响应失败回滚。

资源释放在最外层提交后进行。释放失败保留精确证明和 pending receipt，仅重试 cleanup，不重放模型。通知是提交后的 ID 提示；异常或通知丢失由持久扫描修复。映射到队列的 Invocation 必须经统一 outcome 入口结算，不能用单独 terminal 入口绕过响应和预算。

## 唤醒、控制与恢复

调度器用 requested 状态记住 drain 中以及最后空扫描边界到达的提示。入队、执行结束和容量释放触发新扫描；持续输入按批让出事件循环。定时扫描负责重启或丢提示后的修复，正常重入不依赖定时器。所有领取仍由数据库和资源 fence 决定，内存 active Map 只跟踪本进程 Promise。

暂停 Thread/成员仍允许符合 ACL 的消息持久化，停止新领取。停止 Invocation 只处理自身来源；关闭 Thread 取消尚未执行的工作并撤销活动授权。成员离开、角色/权限/账户漂移均阻止新领取。恢复资格保留原队列年龄；Owner resume 的控制 epoch 证据单独保存，不能复用旧 resume 为后续权限变更静默授权。原 T05 Wake 与冻结回执保持不变。

启动顺序先完成账户、原生执行和费用事实对账，再恢复 Threaded 投影。恢复先撤销旧执行 epoch。已证明未启动且资源仍为 reserved 的 Attempt 可写 not_started 证明、撤回未用请求预留，在原 Invocation/Run/root 下准备新 Attempt。已 started、执行未知或资源已 unknown 均保留对账计划，不因租约到期抢占或自动重放。已提交的响应/终态只修复通知和释放收据。生产组合没有 executor，恢复不会触发模型。

## 因果根预算

根从持久用户消息推导，Agent post/response、跨 Thread 接力及安全重试继承原根。systemKey 不能自建免费根。默认策略冻结为：

| 维度 | 默认值 |
| --- | --- |
| 根输出 tokens | 300000 |
| 单次请求最大输出 tokens | 24576 |
| 根 Invocation | 20 |
| 每 Invocation Attempt，含初次 | 2 |
| 根累计活动执行 | 1800000 ms |
| 费用预留上限 | 5000000 微美元，即 5 USD |
| A2A 深度 | 15 |
| 活动许可片段 | 1000 ms，持续执行须提前续期 |
| 未知价格 | 默认停止；显式 reserve 策略须指定正数费用预留 |

Invocation、Attempt、实际请求各有独立账本；Run 不重复扣费。每次实际请求须独立 reserve/start/settle。可信 usage 验证器默认拒绝，非空 evidenceReference 不能充当供应商证明。已知消耗照实落账，超预留后阻止后续请求；未知 token/cost 维度保留预留，不视为零。

预算端口已验证同 Attempt 的多次请求分别结算。T06 最小 runner 每个 Attempt 只运行一个注入请求；T07 的多请求适配器须随当前请求切换授权和 heartbeat，不能继续 checkpoint 已结算的初始授权。Attempt 终态聚合全部请求的结算状态，未决副请求费用不能被初始请求的已知回执掩盖。

同 Attempt 的模型和嵌套工具活动区间取并集，不同 Attempt 各自计量后相加。活动许可持久化且须在到期前 checkpoint；到期不能静默续租。未知执行保留开放活动记录和约束。确认静止但费用未知可释放执行资源，费用预留继续保留。持久等待本身不创建活动区间，不重置累计值；绝对 deadline 按墙钟，不随暂停延长。

Owner 的追加预算、暂停/恢复根、deadline 修改及可选 24 小时窗限制都是有幂等键、版本和理由的追加决策，已有根不随环境配置变化。默认记录 owner 24 小时用量，不默认设置额外窗口上限；未决预留不会因滚出窗口免费消失。这里只保证本地预留与停止派发，不承诺供应商硬账单封顶。
