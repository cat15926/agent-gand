# AC5 可校验多轮流程 v1

日期：2026-10-18。对应[实施方案](../plans/agent-autonomous-collaboration-implementation-plan.md) AC5。模型 API 适用实现及隔离验证已完成；真实供应商与原生自主组合仍属 AC6，Codex 真实验证继续暂缓。

## 契约和入口

新普通任务仍走 entryVersion2。服务端追加冻结 `features.autonomousCollaboration.flowVersion=1`，根策略的 `protocols` 保存允许流程的 ID、规则和定义指纹。旧 AC1–AC4 根不补字段、不升级。默认 `AUTONOMOUS_COLLABORATION_MODE=closed` 不变，execute 房间入口才准入；此次不迁移日常业务库。

输入区展示自动规则公告和终局披露范围。用户提出需求，负责人选择已有成员与流程，不要求用户发牌、填写逐人材料、确认阶段或搬运结果。可用成员不足时不能虚构玩家或自动复制账户。

`protocols/definitions.ts` 是受信版本目录，定义参与者范围、阶段、行动结构、转换、公告规则和最大步数；模型不能上传可执行流程、改规则或提供身份分配。当前目录：

| 流程 | 规则与终点 |
|---|---|
| `werewolf-five-v1` | 五人、1 狼人/1 预言家/3 村民；夜间同时行动与查验→白天声明→投票→必要时第二夜；最多 4 次裁决；狼人死亡好人胜，狼人达到存活人数一半狼人胜；同票按初始座次；终局披露身份及实际行动回放 |
| `review-ballot-v1` | 2–8 人独立读取获准材料；各自提交 approve/revise/reject；平台公布固定计数，reject 优先于 revise；意见通过不等于用户业务验收 |

游戏是同一组件的样例，调度器没有关键词检测或游戏专用派发循环。普通报告修改继续使用动态 DAG、内容汇总和受控文件，而非强制变成表决流程。

## 工具和状态

`agent.flow` 启动时传 `commandKey/protocol/players`，续推传 `commandKey/flowId/expectedStep`。仅当前根责任能调用；服务端验证清洁的实际输入来源足以覆盖根公告范围、冻结成员、规则指纹、现阶段所有已接受行动和步数上限。

平台用加密安全随机抽取身份，创建每位玩家私密材料。`agent.flow_action` 只接收当前阶段本人的领域行动，不接收 Run、Grant、Scope、代际或权限。玩家工作只开放该工具；执行层严格限制字段、类型、存活目标、非本人目标和阶段，不把模型 JSON 视为自动脱密依据。合法行动与 `agent.complete` 的底层验收、候选、封存结果在同一事务中写入，失败不留下半条行动。

每阶段通过原 `commitAutonomousDelegation` 创建 Subject、派生 Grant、工作、子义务和 Dispatch。玩家输出留在私密 Scope；父责任由既有状态回执及代际唤醒。负责人再次调用流程工具，平台校验完整行动集与已知用量并应用固定 reducer，原子追加新状态、公告和下一阶段派发；终局裁决同样绑定 Scope 动作命令和工具回执。没有登记等待、没有已接受行动时不推进；不是靠计时轮询或脚本填写行动。

负责人可同时担任玩家：两份责任有不同 Subject、冷上下文和来源账本；玩家私密材料不进入主持协调责任。预言家查验结果仅在其后续私密材料中。结构化声明允许策略性自称，不能当作身份事实。

动作格式或目标错误最多追加 **2 次纠正调用**，全部记入根账本；拒绝的原文不进入公开公告。用量未知、来源改变、撤销、停止及真正执行失败不会被当作可随意重试的格式问题。当前不承诺任意故障自动换人并继续游戏，更不替失败成员作出决定。

## 来源、公告和终局

schema22 追加 `autonomous_flows / autonomous_flow_steps / autonomous_flow_sources / autonomous_flow_jobs / autonomous_flow_actions`，全部禁止更新和删除。执行状态继续取原 Subject/Custody/Dispatch；新表保存协议事实，不建立第二套调度器。已发布/已完成阶段不可改写。规则变更需要新版本，新任务不得重解释旧协议。

每份生成材料、公告有确切消息引用和指纹，按规则从已封存状态重算。状态保留前一版本指纹及真实行动的 Work 引用；每次使用验证接受结果、来源、证据和祖先授权。派生 Grant 仅可接收这些已登记来源或原合法来源，不能任意注入新正文。迟到响应、重复推进、死者行动和同责任重复投票不能形成第二份事实。

公告由固定转换得到：首轮规则与座次、死亡、玩家结构化声明、实际票数与放逐、存活与终局。自由文字、模型错误、私密身份/查验原文不进入公告。公告按根输入原权限发布，不扩大原有材料 ACL。网页将规则公告直接呈现，私密内部执行仍默认折叠。

终局最终报告取服务端校验的结果，包含声明过的规则、各次裁决和已接受独立行动的完整回放；不依赖负责人声称的胜负，不自动拼接全体私密子结果。机器完成与用户质量验收仍分开。

暂停持久保存原责任；恢复沿用原身份、阶段、行动和工具回执，不重新抽牌。恢复、重复启动和终局发布复用既有命令幂等键与代际，所有阶段仍共用同一根 token、费用、时限和派发预算。用户补充可以影响后续合法行动，但不会改写已冻结规则、身份或已发布事实。

## 验证边界

`pnpm verify:autonomous-ac5` 通过真实 HTTP/Scope/调度/账本/工具事务链路，Provider 为隔离模拟；涵盖完整游戏、同组件非游戏评审、普通报告修改和独立复核、冷进程恢复、停止、私密来源漂移、未知用量、非法行动纠正、双阵营胜负及迁移兼容。

`pnpm verify:autonomous-ac5-ui` 验证一次发送至终局、公告、真实阶段、默认私密折叠、刷新后回放和 1440px/390px 布局。以上不证明真实模型策略质量、SDK/Codex 自主可用或日常环境已开放。证据见[AC5 验收报告](../reports/autonomous-collaboration-ac5-acceptance-2026-10-18.md)。
