# 私密及写入阶段恢复 v1

2026-10-11，R4 生效契约，承接[阶段续跑](./business-stage-continuation-v1.md)、[阶段返工](./business-stage-rework-v1.md)、[受控文件 ACL](./private-interaction-artifact-acl-v1.md)与[产物快照](./artifact-worktree-snapshots-v1.md)。验收证据见[R4 报告](../reports/platform-collaboration-r4-acceptance-2026-10-11.md)。

## 适用范围

恢复入口要求冻结的 `stage_gated` Coordination 契约。续跑来源须已失败；返工还可来自等待验收的暂停任务，当前阶段须有被拒绝的实质交付。仍排除运行中、已取消、目标固定、全部阶段已验收、已创建后继及没有冻结派发边界的执行后验收清单。

| 来源 / 后继能力 | 当前行为 |
|---|---|
| 公开只读阶段 | 保留原 v2 续跑及返工；原有未知消耗门禁不变 |
| 私密只读阶段 | v3 加密检查点，保留整个任务的共同授权范围；未知调用消耗仍需所有者核对 |
| 公开写入阶段 | 所有者先核对实际工作树和工具记录，v3 恢复到新目录，仅执行剩余文件工作 |
| 私密写入阶段 | 模型 API 与配置了平台 `fs.write` 的 SDK/app-server 可以加密写入受控版本；原生文件、命令和网络关闭 |
| SDK / Codex 后继 | 使用新 Run 会话与专用执行目录；公开原生编码须有可验证 Git 基线，文件写入仍遵守审批和路径检查 |
| 混合公开任务内的更窄私密子范围 | 阻断，不自动扩散到共同范围；须由所有者提供合法授权的新任务输入 |
| 自由协作、其他引擎的通用图或部分成员返工 | 未开放私密/写入通用图检查点，继续明确拒绝；R6 的部分成员选择在本范围回退整阶段 |

所有新 v3 后继关闭命令及外部副作用工具。内置模型只有获准的 `fs.read`、`fs.write`、`search.files`；主动请求未下发的命令同样在执行门控拒绝。SDK 去除 Bash 并拒绝 Bash 权限请求；Codex 关闭 shell 工具、拒绝命令事件和命令审批。既有角色配置不被覆盖。

## 恢复前核对

`businessProcessesQuiescent` 核对原生执行、登记的进程、各类运行中 Attempt 及工具。运行中或尚未确认收敛的进程不能通过人工声明绕过。来源私密消息、上下文及文件必须能够合法进入原冻结范围，私密恢复不能扩大受众。

服务器读取冻结步骤及实际 Attempt、平台工具账本、原生活动/独立采集的变更证据和受控文件，逐项呈现：

- **已确认完成**：完成状态和实质输出已落库，按原来源和哈希迁移。
- **可执行的剩余步骤**：未派发，或已确认没有需要重放的写入动作；不将此标签当作没有发出过模型请求的证明。
- **结果未知**：未完成的写入调用或工具调用已发出，需要所有者核实实际文件、外部服务和交付结果。默认保持阻断。

公开工作树按 R3 路径策略、大小/数量限制扫描新增、修改和删除，并保存可验证的 Git 基线与当前变化。私密任务只读取加密受控版本，不打包物理工作区。检查清单会披露排除项和限制；扫描或归档超限明确拒绝。工作状态快照的完整性不代表阶段已经验收，已验收的原始证据另外保留。

所有写入来源均须填写整体核对依据并明确确认已核对外部副作用。未知步骤必须逐项作出结论：

- 确认完成需提供至少 30 字的实质交付、至少 10 字的核对依据。该正文标记为 `owner_reconciled`，与模型输出区分；原失败 Attempt 不改为完成。
- 确认未执行需至少 10 字依据。已观察到文件版本、完成的写入工具或原生变更证据时禁止此结论，避免把实际发生的动作重新执行。
- 仍未知则不能保存可执行结论。应核实或人工收尾；平台不会替用户推断外部系统结果，也不会自动回滚副作用。

核对记录不可变、加密保存，绑定来源 Run 与整个检查指纹。文件、步骤/账本、授权、房间成员或控制状态变化使其失效。重复请求返回同一记录，同键改结论拒绝。保存核对本身不调用模型，也不改原执行或工具账本。

## 检查点与证据

新检查点 v3 使用受保护主密钥 AES-256-GCM 加密整个检查点正文，AAD 绑定目标 Run 和摘要。摘要同时冻结到编排请求。读取校验密文、正文哈希、来源授权、输出哈希及归档摘要；v1/v2 历史检查点继续可读。消息和 Trace 仍使用现有 ACL 存储，不宣称所有平台数据均加密。

已验收前缀保留原报告、决定和归档，已完成成员从新执行图移除。经所有者核对完成的未知步骤仅以明确的核对交付复用；没有伪造原模型完成结果。目标可登记这些同阶段确认结果，但须重新关联并逐项验收才能继续下一阶段。

受控文件按精确来源版本迁移，保留 ACL 并记录 `restoredFrom`。被拒绝候选正文只作为返工参考，不加入完成白名单；候选文件不能冒充新 Run 的文件验收证据。私密字节继续加密，通过获准的文件工具读取，不进入原生工作目录。

写入恢复另保留核对后的工作状态，允许当前文件与过去已验收的版本不同；过去的验收归档仍独立保留。原生后继只使用恢复的 Git 树与声明变化，不依赖原仓库的对象目录、远程配置或 hooks。

## 原子确认、预算与工作区

续跑/返工沿用当前角色和账户重新预览，配置变化拒绝过期确认。新 Run、检查点、受控版本、归档引用、预算结转和唯一后继在同一事务提交；返工原等待执行的关闭也在该事务内。部分失败整体回滚，提交响应丢失或服务重启后的精确重试返回既有后继。

原失败终态和验收账本保持封存。等待验收的返工来源在确认后关闭执行并保留拒绝记录，新阶段必须提交新交付和验收。未发生过的新工作仍按冻结时限执行。

已知输出 Token 按实际用量结转；来源 `pending/unknown` 及已结转未知记录按预留上限计入新预算，用 `carried_unknown` 保持未知标记。原未知账本不改为已结算，恢复不会重置已消耗额度。后继只放行已经核对过的历史未知预留，新产生的未知调用仍阻断；预算耗尽不能通过续跑绕过。货币费用遵守[R5 费用契约](./cost-budget-governance-v1.md)：已知及未知占额一起结转，费用账本参与核对指纹，所有者核对不释放未知费用。

v3 写入后继恢复一次后取得该目录的使用权。每个完成的成员步骤记录文件内容、模式与 Git HEAD 摘要。阶段恢复核对该边界摘要，保留步骤实际产生的改动；不会把最初快照重新覆盖到已经写入的文件。边界后出现人工漂移、缺失或路径链接时阻断，要求核对并建立新关联任务。

## 所有者页面及接口

失败任务卡提供“检查恢复条件与副作用”，显示完成/剩余/未知步骤、实际文件变化、原始验收归档、私密范围、工具账本与未知用量。核对后重新预览续跑；被拒绝阶段的返工面板提供同一入口。预览说明授权、剩余成员、文件工具限制和结转预算，确认后才调用模型。

任务详情的“查看所有者恢复核对记录”可回查最近 10 条不可变记录及其依据和实质交付，全部历史仍保留在加密审计表。原任务与后继之间保留导航。

| 接口 | 行为 |
|---|---|
| `POST /api/accounts/business/:runId/recovery-inspection` | 空对象输入；只检查，不接受 viewer、受众、工作区或权限覆盖 |
| `POST .../:runId/recovery-reviews` | 携带检查指纹、幂等键、整体依据、外部副作用确认和未知步骤结论 |
| `GET .../:runId/recovery-reviews` | 所有者读取最近 10 条加密核对记录 |
| 既有 `continuation-preview/continuations` 与 `rework-preview/reworks` | 重新检查核对有效性，预览并原子确认后继 |

以上接口沿用 Owner Cookie、Host/Origin、远程管理认证、CSRF 和 no-store；记录及私密清单不通过 Agent、普通 task-state 或 WS 广播。工具调用不能修改核对、授权或检查点。

## 迁移和边界

追加迁移 v8 `private-write-recovery-v1`，新增 `business_recovery_reviews` 与 `business_write_workspace_states`。旧 worker 在写库前拒绝未知版本。受控文件、快照或核对记录存在时丢失主密钥，不能创建替代密钥掩盖不可恢复状态；备份需保留原数据库和主密钥。

本契约不支持任意 shell/外部事务恢复，不承诺外部操作的自动 exactly-once。未知外部结果依赖所有者实际核实，后继文件工具限制防止平台默认重放。[R6](branch-rework-contract-revision-v1.md)已交付适用公开只读图及契约修订；私密/写入阶段修订继续执行本核对契约，部分成员返工回退整阶段，通用跨引擎图明确拒绝。性能治理留给 R7；真实账户、真实供应商与更广联合场景留给 R8。
