# 编排入口 O7：整体验收与交付工具

日期：2026-10-06。范围：整体本地验收、隔离演示、真实账户最小测试入口、迁移与弃用清理盘点。**真实供应商验收与用户确认清理分别记录，不由 fixture 结果推导。**

## 可执行入口

| 命令 | 行为 | 数据与费用 |
|---|---|---|
| `pnpm verify:orchestration-o7` | 新版真实 HTTP 路径验证自动、接力、分析汇总、开发评审、审批、暂停恢复、绑定与幂等 | 临时数据库与模拟原生进程，供应商推理为零 |
| `pnpm orchestration:acceptance` | 顺序运行 O1–O7、本地实际 SDK/CLI 协议、账户认证与 O5/O6 页面回归 | 隔离 fixture；缺浏览器依赖记为未执行，不能返回整体通过 |
| `pnpm orchestration:demo` | API `127.0.0.1:3011`、页面 `127.0.0.1:5174` | 临时数据库、模拟账户和模拟 SDK/app-server；退出删除演示数据 |
| `pnpm orchestration:acceptance-real --claude-agent <ID> --codex-agent <ID>` | 在正常项目服务上，分别提交一个托管账户只读任务 | 会请求供应商，可能消耗少量额度；不创建或导入真实认证 |
| `pnpm orchestration:cleanup-inventory` | 只读审计、入口统计、待检查任务与清理条件 | 不迁移、不解密密钥、不调用模型、不删除兼容分支 |

浏览器回归需要 `PLAYWRIGHT_MODULE` 指向已安装的 Playwright 模块；自定义 Chromium 可通过 `CHROMIUM_EXECUTABLE_PATH` 提供。聚合脚本不自动安装依赖。具体证据见[验收记录](../reports/orchestration-entry-phase-o7-acceptance.md)。

## 隔离演示

演示通过 `AGENT_GAND_ISOLATED_WORKER=1` 跳过业务 `.env`，使用临时 SQLite、私有认证目录、平台文件沙箱和原生工作树。启动时检查配置路径确实属于本次临时目录，再打开数据库，防止模块提前初始化导致误用业务配置。原生命令固定为本地 fixture；父进程拒绝非本机请求。退出后关闭原生进程、HTTP/WebSocket、Vite 和 SQLite，删除本次目录。

演示成员包含分析员 A/B、汇总者、主管、独立评审者、需审批执行者，以及明确标注“模拟”的 Claude SDK / Codex。SDK 与 app-server 模拟账户也经过实际托管账户绑定，证明统一入口没有越过账户和 attempt 权限边界。它们不代表实际供应商认证成功。

演示步骤：

1. 新建聊天室，选择分析员 A/B；输入“分析当前接口”，发送自动任务。
2. 为本轮明确选择 A/B，选择顺序接力；输入“比较接口”，预览并确认，查看前后依赖。
3. 加入汇总者，工作流选择分析与汇总，指定汇总者，确认后查看阶段。
4. 选择需审批执行者，顺序接力，输入“写入演示文件”；在原任务卡批准文件写入。
5. 顺序任务输入 `O7:pause 只读比较接口`，暂停后明确恢复；观察原任务继续。
6. 选择分析员 A 和独立评审者，开发与评审工作流，选择演示 Git 工作区并指定评审者；完成后查看固定结果与评审门禁。

固定轮次辩论、主管详细计划和 SDK/Codex 角色可继续通过同一入口操作；演示的主管为模型 API mock，外部成员不能担任主管。模拟角色只返回演示产物，不执行任意真实需求。

## 真实账户最小任务

真实测试要求显式指定已启用角色，其 driver 分别为 `claude-sdk` / `codex-app-server`，且 `accountRef` 指向托管账户。不会自动选择账户、读取通用 Codex 登录目录或接收 Key/Token 参数。只指定一类后端时另一类记为 `not_run`，总体为 `incomplete`。

脚本检查 `/api/orchestration/options` 的验证环境；`NODE_ENV=test` 或自定义 SDK worker 不能被记为真实 SDK 通过。Codex 继续使用已有版本准入，不能跳过未知协议版本限制。

每类后端创建独立空房，规则预览一个明确单人、自动、常规协作、只读的算术说明任务；生成随机幂等 ID，确认提交，重复提交验证返回同一 Run，然后轮询。没有详细 planner、写入工作流或自动审批。最小请求只是提示模型简短作答；外部后端不支持硬 Token 上限，故不声称有严格费用上限。任务截止时间默认 120 秒，可在 10–180 秒内调整。

通过要求同时满足：Run 完成、冻结托管账户匹配 driver、统一执行权威、实际原生执行全部完成且只读、有效 execution binding、非空持久输出。运行期间首先保存 Run / 房间 / 幂等 ID，便于异常后的检查。报告不保存目标正文、模型响应正文、Key、Token、认证路径或供应商错误正文。

若任务失败、等待用户或超时，仅请求取消本次验收任务，不自动批准、不重试推理、不新建替代 Run。取消不证明所有副作用已知；需要检查时继续使用 O6 的审计与隔离状态。如果提交响应丢失且未取得 Run ID，报告请求结果未知，须检查本次验收房间，不能直接重跑整条命令。
