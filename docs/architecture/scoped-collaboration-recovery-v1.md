# 独立材料协作恢复契约 v1（G4）

实现日期：2026-10-16。适用于[独立材料协作](scoped-collaboration-control-v1.md)和[授权发布](scoped-information-release-v1.md)的模型 API 路径。对应[实施计划](../plans/scoped-collaboration-implementation-guide.md)与[G4 验收报告](../reports/scoped-collaboration-g4-acceptance-2026-10-16.md)。

## 能力与版本

新确认的 Run 在冻结契约及不可变 DeliveryPlan 中声明 `recoveryVersion=1`；既有 `deliveryVersion=1`、Scope/manifest/provenance 与授权发布版本保持不变。数据库追加迁移 v16，用于标识新的恢复语义和调用账本关联，旧 descriptor/checksum 不改写。旧 worker 必须拒绝 v16 数据库，禁止混用版本或直接降级。

历史 G2/G3 计划不补写版本。原 `all` 计划继续按原义务执行；历史调用缺少可验证的费用关联时不自动重发。终态 Run 不重开、不迁移结果，不借恢复修改授权、预算或截止时间。

## 只读 any

正常“独立材料协作”抽屉新增“批次完成条件”：

- 全部满足后继续（all）：保留最多两批、六项及原有三种交付要求。
- 首个有效结果后继续（any）：仅第一批，最多 `min(3, maxTargets)` 项，每项必须为 `result`；同批成员不重复。

`any` 仍只接收表单文字与冻结角色提示词，只向模型开放对应控制工具。没有文件、平台工具、原生会话或外部写入。提交参数必须与预览确认的 join、items、returnProfile 完全一致。不能由模型将 all 改为 any，也不能仅凭 ACK 胜出。

完成 Candidate 验收、winner CAS、其他未完成项取消、胜者结果消息与完成命令回执在同一事务内提交。父级仍仅收到 `{key,state}`，不接收正文或错误文本。全部候选失败时 join 失败；胜者存在时，取消其他项不会使 join 失败。未胜出项的迟到输出不能创建贡献消息、草稿或进入后续授权汇总。

取消不等于供应商免费。已发出的 loser 请求可能已计费，用量不明则保留预约。首版 any 只有一批，最后的固定状态核对由服务端走同样的 Scope/完成命令校验，不新增模型调用，因此不会为核对状态突破未知费用围栏。

## Attempt 恢复

租约恢复只处理已经失效的 Attempt，重新领取时产生新 generation、Scope、manifest 和成员资源占用。保留同一 Dispatch、信封和冻结计划，不复制成功项。

| 崩溃位置 | 恢复行为 | 费用行为 |
|---|---|---|
| 领取后，未预约模型请求 | 允许在原重试上限内重新领取 | 无模型预约，无扣减 |
| 预约已提交，调用仍为 waiting | 原预约结算为 0，再允许安全重试 | 保留原调用记录，不能算作已发出请求 |
| 调用已标记 started，可信结果/用量未完成持久化 | 失败收敛，不自动重发 | pending 预约转 unknown，保留全部占额 |
| 可信响应及费用已记录，业务完成命令尚未提交 | 只重试该未完成事项 | 原调用费用保留；新调用新增一次费用，不能把两次调用合并为一次 |
| 完成命令已提交 | 原结果、命令回执和成功事项直接复用 | 不再调用模型或增加预约 |
| 工具账本存在未知外部写入或原生执行 | 继续执行既有副作用围栏，不自动重放 | 保留待核对记录 |

安全重试仍受既有 `maxAttempts`、截止时间、权限与预算限制。这里的“部分失败恢复”指可恢复的进程中断；确定的业务失败、权限漂移或已经结束的 Run 不会被擅自重开。

通用成员恢复不再把可安全恢复的 scoped 任务提前锁成等待人工处理；失效票据由 scoped Attempt 的恢复判定接管。成员 lease 使用 Attempt 区分，新旧执行的清理回调也检查 Attempt，避免旧回调清理新占用。模型实际派发前再次检查 Attempt、Dispatch、Run 和租约；失效调用不能重新进入供应商。

## 调用与预算对账

新请求以 `orchestration_model_calls.id` 作为该次 Run/阶段 Token 预约和费用预约的共同 ID。钱与 Token 的正常结算在同一事务中执行；恢复按具体调用关联，仅更新 pending 记录，已知账单和已保留的 unknown 不被覆盖。

恢复扫描本身不创建调用或预约。一个成员失效，不会把仍在执行的兄弟成员预约结算或释放。无价格政策时可以没有费用预约；有价格政策时保留冻结报价与既有估算/unknown 规则。该账本表示平台准入及可信返回用量，不承诺替代供应商账单。

## 事务与竞争

批次、信封和子责任创建原子提交；固定状态投影和父恢复原子提交。运行状态变更通知移至外层事务提交之后，回滚不会广播已完成的假状态。

授权发布沿用 G3：Grant 消费、消息、ReleaseRecord 和注册唤醒事件同事务。发布、停止、撤销按数据库事务顺序判定。若停止/撤销先提交，未消费授权不能发布；若发布先提交，后续停止/撤销保留已发布事实。相同 Grant 重放返回同一结果，不再次发布。

专用 Hold 领取使用租约；领取后进程崩溃可在租约失效后重取。恢复命令、唯一 resume Dispatch 和 Hold 完成同事务。Stop 与 wake 竞争至多产生一个随后被停止的恢复 Dispatch，终态之后不再新增调度动作。

本契约尚不开放多批 any、SDK/CLI 独立 Scope 或 Coordination 的新范围流程；这些属于后续 G5/G6。
