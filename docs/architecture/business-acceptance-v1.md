# 任务阶段与业务验收 v1

对应 [Issue #14](https://github.com/cat15926/agent-gand/issues/14)。统一任务入口支持可选的 `businessContract`，将执行终态与业务目标结果分别记录。此版本提供任务级阶段清单、必要交付、所有者逐项验收及追加账本；清单不增加协作模式，也不改变现有工作流调度。

## 用户操作

1. 在聊天室输入目标，打开“执行设置”，启用“本任务启用阶段验收”。
2. 为每个阶段填写名称、每行一条的验收标准以及必要交付项。文本项引用本任务成员消息或已完成 Attempt 输出；文件项引用当前绑定工作区内的普通文件。
3. 预览并确认任务。阶段清单随请求冻结，角色、账户、约束或清单变化会使预览失效。发送后，新一轮不继承清单；浏览器草稿保存本轮清单。
4. 执行结束后，在任务卡打开“查看计划、结果与验收”。为交付项选择证据或核对相对文件路径，登记交付候选。
5. 核对证据并勾选全部标准，按阶段顺序确认验收。全部阶段通过后显示“目标已达成”。内容不满足要求时，填写原因并拒绝候选，再登记替代交付。
6. 需要提前结束时，先取消执行；进程与工具收敛后，在验收面板填写原因，将业务结果固定为“用户提前结束”、“明确目标未达成”或“接受已验收的部分结果”。固定后不可覆盖；补充事项需要新任务。

“仅记录确认收到”只生成确认记录，不含交付证据，也不能验收通过。关闭该确认记录后再登记实质交付。对“收到”“好的”“ok”等整条短确认输出，登记交付也会被拒绝；对一般自然语言内容是否满足业务语义，仍由用户逐项判断。

任务卡同时显示执行状态与业务目标。例如执行失败但分析阶段已验收，用户仍可接受该部分结果。执行失败本身不直接裁决业务失败；有清单且执行收敛的未验收任务显示“目标待验收”。历史任务或未定义清单的任务显示“目标未验收”，不从非空输出推断达成。

## 冻结契约

```json
{
  "businessContract": {
    "version": 1,
    "stages": [
      {
        "id": "analysis",
        "title": "问题分析",
        "criteria": ["说明根因与影响范围", "列出方案与验证边界"],
        "deliverables": [
          {"id": "report", "title": "分析报告", "kind": "text"}
        ]
      }
    ]
  }
}
```

每任务 1～8 个阶段；每阶段 1～12 条非空且不重复的标准、1～12 个必要交付项。标识只接受字母、数字、下划线及连字符，阶段及阶段内交付项标识不可重复，不能使用 `__proto__`、`prototype` 或 `constructor`。阶段标题和交付项标题上限 200 字，标准上限 500 字。未知字段拒绝。

契约进入统一入口的语义指纹、确认预览、幂等摘要及 `orchestration_requests.snapshot`。没有清单的旧请求不增加契约字段，保留原语义指纹形状。暂停图修订必须保留原清单；清单变化需新任务。房间默认偏好不包含该字段。

各引擎共用的 `runAgentTurn` 将冻结清单作为系统说明下发，要求实质交付及准确标识阶段。不会注入用户后续验收记录、私密交付摘录或所有者说明，也不赋予 Agent 新的路由或终局权限。Agent 的完成声明仍只参与原 Runtime 执行协议。

## 追加账本与裁决

`business_acceptance_events` 按 `(run_id, version)` 递增，记录确认/交付、验收决定与业务结果。每操作需要 `expectedVersion` 和 `clientRequestId`；版本不匹配返回 `BUSINESS_STATE_STALE`。同请求同内容只记录一次，同请求不同内容返回幂等冲突。

交付登记固定证据引用、来源、完整内容 SHA256 及有界脱敏摘录。验收接受时检查：

- 执行已终止，未留运行中的 Attempt、原生进程、未知中断执行或需核对的工具结果。
- 候选属于当前阶段、是最新的未处理交付，且不是确认收到。
- 前置阶段已验收，全部标准已逐项勾选，全部必要交付项具备证据。
- 文本引用本 Run 的成员消息或已完成输出，不能用用户需求、系统状态或其他 Run 的产物冒充。
- 文件属于当前绑定工作区、路径不越界、为不超过 32 KiB 的普通文件，哈希匹配。
- 所有证据在登记后未发生内容变化；漂移后必须拒绝旧候选并重新登记。

已验收阶段不能替换交付或改写决定。被拒绝或替换的记录留在账本，可通过验收历史查看。业务结果固定后不允许新操作，但原请求的幂等重试仍可读取结果。

业务账本不修改 `runs.status`、`terminal_disposition`、Runtime Subject 或原终局记录；“接受部分结果”至少要求一个已验收阶段，并明确记录接受原因。全部阶段验收通过才能派生 `achieved`，不能通过直接设置目标结果跳过检查。

## API

| 入口 | 行为 |
|---|---|
| `GET /api/accounts/business/:runId` | 冻结清单、阶段当前候选/决定、版本与业务结果 |
| `GET /api/accounts/business/:runId/evidence` | 当前 Run 最近的成员消息及完成输出候选，消息和输出各最多 100 条 |
| `POST /api/accounts/business/:runId/file-evidence` | 输入 `{ "path": "reports/result.md" }`，核对文件并返回带哈希的引用，不写账本 |
| `POST /api/accounts/business/:runId` | `report`、`decide` 或 `resolve` 操作 |
| `GET /api/accounts/business/:runId/history` | 最近 100 条追加记录，含历史证据摘录和哈希 |
| `GET /api/conversations/:id/task-state` | 每任务的轻量业务状态、版本和已验收阶段计数 |

这些接口复用现有管理会话、Host/Origin 白名单和写操作 CSRF 校验，没有注册为 Agent 工具。浏览器自动建立本地管理会话；远程管理沿用账户模块的认证要求。所有者可看到私密消息和证据。当前本机进程仍属于同一信任边界，不表示多租户或恶意同机进程隔离已实现。

## 当前边界

- 阶段验收发生在执行收敛后，不暂停每阶段调度，也不阻止 Runtime 将 Run 标记为执行完成。自动阶段转移、执行中的阶段门禁、确定性确认与差异化派发仍需后续协议支持。
- 文件保存哈希与有界摘录，不复制或迁移整个产物，不保证文件在验收后保持原位。工作树恢复、文件 ACL 与完整产物归档仍在后续范围。
- 含阶段清单的 Run 暂不允许现有关联续跑或终态主管分支重试跨 Run 迁移；避免遗失契约或误复用阶段结果。原 Run 内兼容重试保留原账本。
- 未知成本的保留额度、阶段预算及真实供应商联合验收不包含在本版本中。

## 验证

`pnpm verify:business-acceptance` 使用导入前设置的临时 SQLite、临时工作区与 Fastify 注入，验证契约冻结、确认漂移、必要交付、标准、顺序、消息/文件漂移、未知执行围栏、三引擎状态、真实 Coordination Attempt 存储、幂等与 CAS、冷启动重建、原终态不可变、草稿恢复及默认偏好隔离，还验证实际 Web 客户端的管理会话建立、CSRF 请求和错误码传递。仅 1 次本地 mock 回合验证 Agent 收到冻结清单，不请求真实模型，也不监听端口。
