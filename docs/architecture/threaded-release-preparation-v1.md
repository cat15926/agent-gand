# 持续协作 RC11 发布准备合同

日期：2026-10-28。基线为已推送 RC10 `ffcbbca`，代码 schema 35，无新增迁移。原 K01–K16、59 项验收文字、E01–E06 增强合同及既有失败证据保持不变。

本阶段实现可重复的发布准备检查与隔离演练。RC10 的完整退出条件尚未满足，因此准备工具和合成演练通过不能签发目标部署的迁移、重启或灰度许可。目标部署验收与隔离证据分列；RC12 不随本阶段自动启动。

## 1. 目标与恢复集合

目标清单必须显式指定数据库、应用版本和恢复路径，登记账户私有目录、角色和头像、专用旧原生目录、threaded 原生配置与 Session、sandbox、托管与外部工作区、产物、release pack 和领域注册。还须保留实际源码与依赖，未提交源码不能仅用 Git HEAD 代替。

预检只读取路径元数据、schema/表结构和计数，不读取日常消息正文、解密账户凭据或启动服务。不得为只读检查导入自动初始化数据库的模块。文件存在不等于密钥、Session 或工作区已与数据库匹配；缺少受控恢复验证时保留 `unverifiable`。显式的操作记录也不能替代真实恢复和外部事实。

仅覆盖 `DB_PATH` 不构成服务隔离。当前 threaded workspace 来自 `config.sandboxDir/threaded`，而 sandboxDir 来自运行源码所在的仓库。实际 index 演练须使用独立源码运行根，或在导入数据库/服务前显式重定向所有可写配置路径并逐项断言隔离；同时跳过日常 .env。此次采用预加载重定向，生产 factory、入场与恢复门禁仍使用实际代码。

## 2. 一致备份与恢复

复用账户维护工具的 SQLite backup API 与文件校验，额外覆盖工作区、Session、发布注册和源码。主密钥或原生认证材料仅放在隔离受保护备份中，不写入仓库或报告。环境主密钥与旧环境凭据依原安全渠道保管。

完整备份要求全部模式的服务和原生执行已停止或有明确处置；未知宿主状态不能当成已停止。持续协作的 `drain.ready` 仅代表 `threaded_only`，不授整库回退许可。在线 SQLite 一致副本也不能证明跨目录文件处于同一时点。

恢复演练必须核对数据库完整性、迁移历史、原根/消息/授权/预算/unknown 与配套文件。先保存迁移后新增数据库、WAL/SHM、私有目录、工作区及产物，再恢复历史集合，禁止把旧库与新 WAL 混用。恢复历史库不撤销已经发生的远端操作或费用；新增集合必须保留供独立核对。

## 3. 版本与运行模式

从固定历史 v34 实现构造的库执行真实 v35 前向迁移，检查 v25–v34 历史片段、迁移记录和业务行不被重写；不删除新表或迁移行来降低 schema。冻结旧 v34 worker 对 v35 必须拒绝并保持零修改。

实际 index 的 `observe` 演练应保留已有根、队列和未决责任，对协作业务表做前后比较，并断言无模型外呼、预算领取、回调或后台恢复写入。它不代表整库只读：schema 初始化、宿主登记和旧模式恢复仍属于主服务行为。

`closed` 演练验证原有旧模式 HTTP 入口仍可操作，并拒绝新的 threaded 房间与根。closed 不是清空已有责任，也不是所有恢复器停写；原可信事实可以按既有合同恢复，unknown 不自动退款或重放。完整旧新真实供应商混跑仍沿用 RC06 的未验边界。

## 4. 验收与放行

| 层次 | 必须留证 | 可得出的结论 |
| --- | --- | --- |
| 只读预检 | 显式路径、结构/计数、缺项与不可核实原因；篡改与不完整输入拒绝 | 当前目标有哪些准备缺口 |
| 合成恢复 | 一致备份、原路径恢复、配套文件校验、v35 迁移、旧 worker 拒绝、新增和 unknown 保全 | 所列隔离恢复路径可重复执行 |
| 实际服务模式 | 隔离 index 的 observe 业务表不变、closed 旧入口及新入口拒绝、外呼计数 | 所列实际入口模式边界成立 |
| 目标部署 | RC10 门槛满足、目标版本/配置明确、全模式静止与未知处置、真实匹配备份和恢复校验 | RC11 的目标部署退出条件满足 |
