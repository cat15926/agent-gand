# 公开只读阶段返工 v1

逐阶段任务的实质交付被所有者拒绝后，阶段保持暂停。重新登记候选只更新验收账本，不调用模型；需要成员修改交付时，所有者须填写修订要求，预览并确认关联返工任务。本入口在[阶段续跑检查点](./business-stage-continuation-v1.md)上增加明确的返工授权与拒绝记录归档。

## 交互

1. 在当前阶段登记实质交付，填写拒绝原因并拒绝候选。
2. 在该阶段的返工区域填写“补充修订要求”，点击“预览阶段返工”。要求必填，上限 2000 字；预览、关闭或编辑预览不调用模型。
3. 预览展示被拒绝阶段的全部成员任务、保留的已验收阶段、拒绝原因及修订要求、文件迁移范围、时限重算和 Token 预算结转。修改要求会清除旧预览。
4. 点击“确认并执行返工”。如果原任务仍等待验收，会在同一事务中关闭原执行并创建新任务；原验收记录及模型输出保持不变，原账本封存。已经失败的原任务保留原终态。
5. 新任务继承已验收前缀，在新的独立工作区和模型会话中重新执行被拒绝阶段的所有成员步骤。后续阶段继续等待新的逐项验收，不能自动通过。任务卡可查看来源及本轮修订要求。

## 支持范围

仅支持 `stage_gated` Coordination、公开只读、已到达阶段验收门禁、进程/工具/调用消耗已收敛且尚未固定业务结果的任务。当前阶段必须是已验收前缀后的第一个未验收阶段，最新候选必须是已拒绝的实质交付。确认收到的记录、正在执行、已取消、全部已验收或已创建后续任务的原任务不适用。

本版返工覆盖被拒绝阶段的全部成员任务，不选择性推断哪个成员应重跑。原成员分工、验收标准、交付清单、时限数值和输出预算上限仍冻结。额外修订要求只下发至返工阶段；变更团队、验收标准或预算上限需重新准备新任务。模型 API、Claude SDK 和 Codex app-server 使用既有执行能力校验，SDK/app-server 仍不接受无法落实的输出 Token 硬限制。

新任务仅复制已验收归档文件，不迁移原仓库基线、未验收文件或写入工作树。文件路径、哈希及大小限制沿用续跑检查点；包含拒绝记录和旧候选正文的完整检查点上限 1 MiB。私密信息、未知调用预约及未知副作用明确阻断。

## 拒绝归档与证据边界

检查点新增 `rework`：原 Run/状态、阶段、原报告及拒绝决定、补充修订要求、被拒绝阶段的输出及其哈希。该内容参与冻结 SHA256，并随新 Run 持久化。

`outputs` 白名单只保留已验收阶段的输出。被拒绝的旧输出保存于 `rework.rejectedOutputs`，作为问题参考单独下发，不能解析成新任务的可验收证据，也不从执行图移除被拒绝步骤。新 Run 不伪造报告、验收事件或完成 Attempt；必须重新登记本轮实际输出并逐项验收。

新拒绝可以发起下一轮明确返工。若返工过程发生执行失败，普通阶段续跑保留本轮明确修订要求与拒绝归档，跳过返工中已经完成的步骤；修订要求仍只作用于对应阶段。来源链和原验收账本可追溯。

## 准入、并发与持久化

Owner 路由：

| 接口 | 内容 |
|---|---|
| `POST /api/accounts/business/:runId/rework-preview` | `stageId`、`reportId`、`expectedVersion`、`instruction` |
| `POST /api/accounts/business/:runId/reworks` | 相同输入加 `previewId`、`orchestrationFingerprint` |

沿用管理 Cookie、CSRF、Host、Origin 和远程管理认证。没有公共返工入口。所有者说明不通过公共预览或请求字段注入内部检查点。

确认重新读取原阶段、验收版本、内容与文件哈希、预算占用、角色和账户版本、工作区及计划。变更说明、原候选、账户配置或验收记录会阻止确认；失败准入不取消原任务、不留下孤儿 Run。

新 Run/Plan、不可变检查点、Token 预约结转、唯一后继关系及原等待执行关闭全部在 `BEGIN IMMEDIATE` 事务内完成，关闭失败则全部回滚；事件仅在提交后发布。每个来源最多一个后继，精确重试返回既有任务，不同确认载荷返回 `IDEMPOTENCY_CONFLICT`。原等待任务的终态记录以 `business_stage_rework` 为来源；已失败原终态不会重写。

新 Run 时限重算必须在预览中说明。Run 与阶段的硬输出预算预约结转，连续返工不能重置已消耗额度；预算耗尽时阻断新返工。结转数字表示输出预算账本，不是全部输入/输出用量或供应商账单。未知货币费用的保留额度和硬上限仍属后续范围。

追加编排迁移 v5；旧 worker 启动写库或恢复前拒绝不支持的版本，避免忽略返工说明。回退仍使用完整备份与匹配 worker，不能降级数据库。
