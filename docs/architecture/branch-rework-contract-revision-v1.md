# 分支返工、契约修订与图承接 v1

状态：2026-10-12 生效。对应剩余实施计划 R6，验收见[R6 记录](../reports/platform-collaboration-r6-acceptance-2026-10-12.md)。本文的架构版本 v1、业务契约 schema v2、业务修订号 `revision`、检查点 v4 和数据库迁移 v10 是不同的版本标识。

[R7 差异化阶段调度](scoped-stage-batch-scheduling-v1.md)追加业务契约 schema v3 和迁移 v11，保留本契约的不可变修订及预算规则。公开阶段的显式汇合是成员结果的下游，部分返工时重新执行受影响汇合；逐成员窄私密状态的跨 Run 迁移仍拒绝，不能扩大授权。

## 1. 用户入口与不变量

沿用任务卡、阶段交付和 Owner 管理会话，不新增顶层协作模式。

- 当前阶段的实质交付被拒绝后，Owner 在返工面板选择成员、填写要求，先预览“保留 / 必须重做 / 需要重新验收”，再确认关联执行。
- 在已收敛的阶段验收边界或失败任务中，Owner 可修改验收清单、交付项或成员分工。预览说明新契约版本及影响；确认创建新的 Run，来源契约、交付报告和验收决定不被覆盖。
- 适用的失败任务卡显示“预览依赖图承接”，明确原引擎到 Coordination 的承接、保留步骤、剩余分支、产物归档和预算。只有确认后才调用模型。
- 活动任务的暂停、恢复及主管分支重试沿用既有入口。等待阶段验收时，恢复能力明确返回 `BUSINESS_STAGE_ACCEPTANCE_REQUIRED`，不能通过普通恢复跳过门禁。主管失败终态的旧“人工重试”入口改为 Owner 图预览。

同一来源 Run 的续跑、返工和修订共用唯一后继约束。相同确认重复提交返回既有后继，不重派工作；不同载荷或不同后继种类返回冲突。暂停来源的关闭、创建后继、检查点、预算和关联关系在同一事务提交，提交后才唤醒执行。失败来源终态保持不变；已取消、已达成或业务结果已固定的任务不能通过本入口重开。

## 2. 业务契约 v2 与部分返工

v1 历史契约继续按原顺序链解释；不自动声明工作独立。v2 要求正整数 `revision`，成员分工可显式声明 `dependsOn`：

```json
{
  "version": 2,
  "revision": 1,
  "executionMode": "stage_gated",
  "stages": [{
    "id": "analysis",
    "title": "分析",
    "criteria": ["结论有依据"],
    "deliverables": [{"id": "result", "title": "分析报告", "kind": "text"}],
    "execution": {"assignments": [
      {"agentId": "a", "objective": "独立分析 A", "dependsOn": []},
      {"agentId": "b", "objective": "依据 A 复核", "dependsOn": ["a"]},
      {"agentId": "c", "objective": "独立分析 C", "dependsOn": []}
    ]}
  }]
}
```

依赖 ID 必须是同阶段排在当前分工之前的成员，不得重复、自引用或引用外部成员；此表示法禁止环。未填写 `dependsOn` 与显式空数组不同：空数组声明独立，缺失保持保守顺序语义。编辑器提供“声明此任务的依赖”，取消全部依赖表示独立。

只有公开、只读、纯文本且全阶段依赖完整声明时，执行图和上下文才使用这些依赖；每名成员取得前阶段结果及同阶段获准的祖先结果。返工 A 必须同时返工 B，保留 C；阶段汇合交付重新验收，全部后续阶段失效。无法证明独立、包含文件交付、私密或写入任务时，服务端回退整阶段返工，并在预览说明原因，不能由勾选框强行跳过工作。

保留列表只显示已有可信完成证据的结果；尚未执行的工作进入重做列表。被拒绝的候选结果保留审计和返工上下文，但不进入完成白名单。已用 Run/阶段输出 Token 和费用不因重做而释放。

## 3. 不可变契约修订

Owner 提交当前业务账本 `expectedVersion`、完整的新契约及修订说明。新契约使用 schema v2，修订号必须恰好是原 `revision + 1`，v1 原契约按修订号 1 计算。

允许修改阶段标题、验收标准、交付项、原冻结团队内的分工和依赖。阶段标识、顺序、执行方式以及阶段时限、Token 和费用上限保持冻结；不能加入原授权外成员或通过修订改变费用计价集合。改变阶段结构或预算须另行明确新任务。

影响从最早变化阶段开始计算：

| 变化 | 继承规则 |
|---|---|
| 仅修改成员目标或依赖 | 在具备独立性证明时按新依赖闭包返工，保留未受影响的已确认成员结果 |
| 修改标题、验收标准、交付项，或删除成员 | 最早变化阶段全部重做、重新验收 |
| 任意更早阶段受到影响 | 后续阶段全部重新处理，原验收决定不继承 |
| 无变化、跳修订号、变更冻结结构或预算 | 预览拒绝，不创建后继 |

旧版本保存在来源快照和审计账本，新 Run 冻结新契约。检查点保留原契约及修订说明，保留结果按阶段及成员重新绑定新步骤 ID；失效验收不复制。预览和确认均重新计算影响、证据、授权、账本和预算，过期预览必须重新生成。

Owner API 使用 `/api/accounts/business/:runId` 下的 `revision-preview` 与 `revisions`，继承管理会话、CSRF、Origin 和 `no-store`。修订接口拒绝自定义权限、任意检查点或未知字段。

## 4. 引擎与检查点兼容矩阵

| 来源与入口 | 当前承接 | 明确拒绝范围 |
|---|---|---|
| Coordination 的冻结 `stage_gated` 图 | R3 v2 / R4 v3 阶段检查点；R6 部分返工和新契约版本 | 运行中修订、验收边界未收敛、任意跳阶段；私密/写入部分返工回退整阶段 |
| Coordination 的非阶段图 | `o4-workflows-v1`、无旧执行 adapter、公开只读失败图；v4 保留完成节点及冻结协议 | 未知图版本、缺少统一执行快照、执行后验收契约、无法确认依赖或产物 |
| Pipeline | 当前 task adapter 的已准入顺序事项；保留完成前缀，Owner 确认转 Coordination | 旧任务未冻结 adapter、确认结果不属于当前成员/轮次、私密或写入 |
| Supervisor | 当前 adapter 的冻结分工 DAG；工作证据与当前轮次独立 PASS 审查一并保留，剩余审查和汇总保留为步骤 | 尚未分配、取消分支、外部依赖、工作/审查证据不一致、私密或写入；不重新付费规划 |
| Collaboration 的批量咨询 | 单个公开只读 `all` 失败/超时/部分批次；父咨询和完成分支保留，剩余分支及显式汇总转 Coordination | `any` 竞速、嵌套/动态追问、多批次、控制动作与批次不符、分支仍有控制义务或活动派发 |
| Collaboration 的基础单事项续跑 | 保留原公开只读暂时故障入口和更窄资格规则 | 原规则未支持的信息范围、未知工具、无法唯一识别待续事项 |
| 活动任务暂停恢复 / 活动主管分支重试 | 沿原执行机制，不转换成新模式；共同收敛/授权/预算规则，阶段验收门禁继续生效 | 无兼容 adapter、未知结果、已有后继；主管跨范围/副作用重试拒绝 |

适用图承接都固定来源目标、原团队、原费用政策和新独立工作区。团队取来源请求的冻结候选集合，保留未实际执行的观察成员；聊天室成员或顺序已改变时拒绝预览，不把候选团队误当作执行成员，也不加入新成员。重新冻结当前角色与账户，剩余步骤使用原工具集合与当前可用只读工具的交集。必须具备原步骤的执行/审查能力；受控文件还要求剩余步骤实际具备文件读取工具。不能因为新的角色能力更宽就扩大原步骤权限。

“转 Coordination”是 Owner 预览中明示的冻结图执行，不调用模型重新制定计划，不静默切换或全量重跑。已确认成员节点转成平台完成占位节点，原依赖和出处保留；不伪造新的成员执行 Attempt。剩余节点只做一次尝试，失败后再次预览承接。无剩余模型步骤时拒绝创建收费后继，提示核对原终态/交付。

## 5. 图检查点 v4、产物与预算

v4 保存来源引擎、完整步骤图、协议、终止节点、可信原 Attempt 输出、产物归档和预算结转。业务契约为 `null`，限定公开只读；已有阶段验收契约不能转换为无验收图。已完成节点的必要前序必须也已确认，否则检查点拒绝。

检查点使用独立的 `business-checkpoint-v4:<targetRunId>:<digest>` 认证加密，确认及冷读取校验来源范围、封装版本、摘要和归档。继承旧图时保留原图的成员与协议，累计新完成输出和消耗，不只复制最新一次剩余图。来源证据继续保持原 Run 和 Attempt 引用。

归档包含公开用户输入附件、已确认输出绑定的受控不可变文件及已确认步骤声明的物理产物。恢复到新 Run 所属目录，不覆盖用户工作区；完整性、哈希和权限继续使用[R3 快照契约](artifact-worktree-snapshots-v1.md)。未声明的物理工作树变化不据此推定已交付。图上限 64 步，检查点元数据和完整输出合计上限 1 MiB；文件大小及载荷上限沿用 R3，超限明确拒绝。传入模型的结果上下文有长度上限，截断会附提示，完整内容仍在归档和来源证据中。

Run/阶段 Token 消耗和[R5 费用账本](cost-budget-governance-v1.md)整体结转，包括失败调用、未知占额、以前后继已继承的费用；不能释放失败消费、提高预算或换模型来重置旧额度。图承接中未收敛进程、工具、pending/unknown 输出 Token 明确阻断；未知费用按原 reserve/stop 政策处理，不按零计算。预算耗尽、确认前账本改变或当前后端无法落实冻结限制时拒绝。

私密或写入的通用跨引擎图检查点尚未开放。适用的冻结逐阶段任务继续走[R4 核对契约](private-write-stage-recovery-v1.md)；R6 不能通过部分成员选择、契约修订或主管重试绕过 Owner 副作用核对。

## 6. 迁移与验证

追加数据库迁移 v10 `branch-rework-contract-revision-v1`，不重写历史迁移描述。只支持到 v9 的旧 worker 会在版本核对时拒绝启动，避免忽略 v2 依赖或 v4 检查点。回退须使用兼容 worker 和匹配备份；旧任务仍按原冻结契约解释。

`pnpm verify:branch-recovery` 及 `--kernel-off` 验证闭包、保留证据、新契约、唯一后继、预算、四类引擎、冷读取和不兼容拒绝。`verify:business-stage-gates-ui` 覆盖桌面/手机实际操作；`verify:platform-network` 增加实际回环 HTTP/WS 下的冷预览、并发确认、修订和冷重试。真实账户、模型与供应商网络长链路仍由 R8 验收。
